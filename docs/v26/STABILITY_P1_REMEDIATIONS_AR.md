# BRAINTRADE V26 — سجل إصلاحات الاستقرار المتتابعة

**تاريخ المراجعة:** 2026-11-04  
**الفرع:** `feature/v26-tp-stage-operator-arm-20261103`، PR #228 (Draft)
**حالة الإصدار:** كود تطويري وفحوص CI؛ ليست موافقة تداول Live أو ضمان تنفيذ Broker.

## P1-1 — منع تأخير القناص بسبب نسخ/تصدير كبير

`crates/runtime/src/lib.rs` يفرض `ensure_bulk_io_idle` على Backup / Brain Export-Import / قوائم النسخ وفحص الاستعادة / التعلم والتصدير الثقيل، عندما يكون START أو أوامر وسيط غير محسومة أو مراكز/أوامر موجودة في آخر Snapshot. تبقى مسارات STOP و`/v1/execution/*` والمصالحة من دون هذا القيد. **هذا احتواء لطلب البيانات البطيء وليس عزل threads حقيقياً**. العزل الكامل ومراجعة تنافس SQLite مهمة مستقلة لاحقة لا يجوز الادعاء بأنها مكتملة.

## P1-2 — مالك واحد لمنصة MT5

`gateway/managed_terminal.py` يشتق قفلاً من `terminal_info().data_path` ويمسك قفل ملف حصري عند نجاح `initialize`، ويحرره بعد انتهاء `cleanup_gateway`. يعمل على Windows عبر `msvcrt.locking` وعلى Linux عبر `fcntl` للاختبارات. يمنع مثيلين جديدين من BRAINTRADE من التداول من خلال نفس مجلد بيانات المنصة حتى إذا اختلفت مجلدات Core. ملف القفل في المجلد المؤقت لا يعني أن العملية ما زالت حية؛ الحكم للقفل الذي يحتفظ به النظام.

تمت إضافة اختبارات لنسختين بنفس `data_path`، ولنسختين بمجلدين منفصلين، واختبار ملكية بين عمليتي Python مستقلتين.

## P1-3 — منفذ Named Pipe فريد ومربوط بالجلسة

`gateway/sniper_native.py` ينشئ `\\.\pipe\BrainTradeSniperV1-<24hex>` لكل جلسة، ويكتب `sniper.pipe` في مجلد `MQL5/Files/BrainTrade` وبداخله token مطابق لـ`sniper.token`. إصدار EA **1.17** يقرأ الملف ويتحقق من تطابقهما وصيغة الاسم قبل فتح Pipe. تُحذف metadata عند نهاية الجلسة فقط إذا كانت تخص نفس token/pipe. يظل `InpPipeName` الثابت للتوافق مع Gateway قديم **عندما لا يوجد ملف sidecar فقط**.

**هام:** EA 1.15 أو أقدم لا تعرف `sniper.pipe`، ولذلك لا يمكن اعتماد `Native` عليها مع Gateway الجديد. استخدم EA 1.17 مترجمة من نفس نسخة المصدر؛ وإلا سيستخدم النظام fallback polling من دون الادعاء بوصول Native.

## P1-4 — تقليل حمل OnTick وإظهار زمن الحجب

داخل `mt5/BrainTradeSniperBridge.mq5`: `OnTick` يمرر دفعة محدودة `InpOnTickBatch=64` (حد 32..128)، وتستمر `OnTimer` باسترداد الدفعات المتبقية وفق الـcursor. تبقى `FileFlush` ضرورية لإيقاظ القارئ فوراً، مع تسجيل `Max FileFlush microseconds` و`Max OnTick microseconds` و`Slow OnTick count` لقياس التأخير، بدلاً من إزالة flush عشوائياً والتضحية بالزمن.

## P1-5 — قياسات HTTP المحلية وتشخيص Core

`gateway/mt5_gateway.py` يسجل `BRAINTRADE_LOCAL_LATENCY` كل 30 ثانية، مع p50/p95/p99 وMax لكل من `core_pulse_ms` و`gateway_cycle_ms` و`snapshot_ms`؛ مخزن مؤقت بحد 1,024 عينة لكل مسار، وبدون سعر أو token أو حساب. `crates/runtime/src/lib.rs` يسجل `CORE_SLOW_ROUTE` للطلب الذي يتجاوز 75ms بفئة آمنة فقط مرة كل 10 ثوانٍ. أزمنة HTTP هذه **لا تساوي زمن وصول الصفقة للوسيط أو تنفيذها**.

## P1-6 — توافق أخطاء HTTP في مسار Core المحلي

`gateway/transport.py` يعيد الآن أخطاء HTTP غير الناجحة من Core بصيغة `urllib.error.HTTPError` المتوافقة مع العميل القديم، مع إغلاق الاتصال ودون أي إعادة تلقائية للطلب. كان HTTP 400 يرجع `OSError` عامة، فلا تتعرف عليه `HvnResultOutbox` وتظل تكرر إيصال HVN مرفوضاً وتمنع الأبحاث الأخرى. يتعرف Outbox مجدداً على HTTP 400 ويُغلق الإيصال المرفوض، بينما تبقى 401 وأخطاء الاتصال غير محسومة ولا تتحول إلى إذن تداول. يوجد اختبار HTTP محلي فعلي لهذه الحالة. هذا إصلاح لتدفق الأبحاث وليس شهادة تنفيذ Broker.

## P1-7 — تخفيف طلبات Core أثناء خمول التيكات

`BrokerHistoryScheduler` كان يعيد طلب `/v1/execution/gateway` مع كل دورة Sniper (~5ms) عندما لا يحدث نبض Tick، حتى دون وجود عمل جديد. أضيف حد 50ms لدورة الفحص العادية وقت خمول التيكات، مع إبقاء نبضات الأسعار السريعة من دون تأخير إضافي، وفحص History الإلزامي كل 5 ثوان أثناء التدفق المستمر. هذا يقلل الحمل المتوقع دون أن يكون قياس أداء فعلياً على جهاز المستخدم. اختبار رجوع يحاكي 200 دورة في ثانية بدون Quote، واختبار الاستمرار في الفحص أثناء التدفق.

## ما لم يُحل نهائياً

- لا تزال `engine.route` و`engine.tick` تعملان على خيط Core واحد؛ دُفع خطر العمليات الثقيلة بعيداً عن وقت START، لكن Core يحتاج فصل بحث/نسخ إلى عامل مستقل وSQLite connections بمعاملة متسقة قبل الادعاء بإزالة Head-of-Line بالكامل.
- `FileFlush` لا تزال عملية مزامنة داخل OnTick؛ تتطلب قياسات على جهاز المستخدم ثم قراراً بخصوص transport مختلف أو نقل النقل إلى Worker رسمي موثوق.
- يلزم اختبار MT5 حقيقي: تبديل الحساب أثناء STOP، وصول BT2/Heartbeat، فصل EA والإنترنت، فشل المرسل ثم المصالحة بدون تكرار `order_send`، وتقرير p95/p99 وقت Broker ACK/Deal مع خصائص وسيط المستخدم.
- نتائج CI قد تختلف بين commit وآخر؛ تُعتمد فقط الحالة المكتملة على آخر HEAD. لا دمج لـmain قبل الفحوص والقبول العملي.

**قاعدة الإصدار:** لا تحديث قديم باسم أحدث؛ ما لم تُفحص الحزمة ضد نفس SHA وتضم EA 1.17 وPython Gateway الجديد، لا توصف بأنها تحتوي هذه الإصلاحات.
