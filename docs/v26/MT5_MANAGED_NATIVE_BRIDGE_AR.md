# V26 — مسار MT5 ثابت + Native Bridge 1.17

> **الحالة:** شفرة وتقارير اختبار. ليست شهادة ثبات اتصال الوسيط على جهاز المستخدم أو ترخيصاً لإعادة توزيع MT5.

## القرار المعماري

لا ننقل أوامر التداول إلى EA في هذه المرحلة؛ يبقى إرسال الأمر لدى `gateway/execution.py` فقط، مع سجل SQLite متين ومصالحة Order/Deal وتفويض Rust Core قبل الإرسال. EA محلي للنقل والتنبيه فقط. السبب: تعدد جهات إرسال الأوامر أخطر من كلفة Python البسيطة؛ أي تغيير يحتاج اختبار عدم تكرار الطلبات بعد الانقطاع.

### 1 — ربط منصة واحدة ثابتة

من صفحة **الإعدادات العامة وربط MT5**:
1. أدخل المسار المطلق الكامل لملف `terminal64.exe` الرسمي الذي ثبّته وسيطك. **لا تترك الحقل فارغاً** إن كنت تريد منع الاختيار التلقائي بين نسخ MT5.
2. خيار **MT5 Portable معزول** اختياري، وهو مُطفأ للملفات القديمة توافقاً مع الإصدارات السابقة. إن أردت العزل، ثبّت نسخة رسمية أخرى في مجلد قابل للكتابة **خارج Program Files** مثل `C:\Trading\BrainTradeMT5\terminal64.exe`، ثم فعّل الخيار. لا تنسخ ملف EXE وحده؛ يحتاج تثبيت المنصة الكامل.
3. أوقف النظام قبل حفظ المسار أو تغيير الرمز. Core يحفظ الإعدادات، يعيد تشغيل Gateway، ثم Python يستدعي `MetaTrader5.initialize(path, timeout=10000, portable=mt5_portable)`. إذا كانت المنصة مغلقة يمكن للمكتبة فتحها رسمياً؛ ولا يستدعي BrainTrade أمر تسجيل دخول جديد أو يكتب كلمات مرور.
4. تُفحص `terminal_info().path` مقابل مجلد ملف EXE المحدد. في وضع Portable تُفحص أيضاً `data_path` مقابل نفس المجلد، ويُثبَّت `data_path` لحياة Gateway. إذا انتقل إلى نسخة أخرى لا يستأنف التداول ولا يستخدم Token/Tick من المسار السابق. اتصال `shutdown()` يفصل مكتبة Python فقط، ولا يقتل برنامج MT5 ولا يُغلق صفقات الوسيط.
5. سيبقى اختيار **Demo/Live** بيدك من الواجهة. لا يغيّر خيار Portable الحساب ولا يلغي التفويضات والمصالحة والقيود المفروضة من الوسيط.

**ملحوظة:** إذا كان المسار فارغاً وPortable غير مفعل، يبقى اتصال الاكتشاف التلقائي القديم لأجل التوافق، لكنه **غير مثبت على نسخة واحدة** ولا نعتمده كمسار الإنتاج النهائي.

### 2 — الجسر Native 1.17

| الرسالة | المصدر | ما تثبته | ما لا تثبته |
|---|---|---|---|
| `BT2` | `OnTick` و`CopyTicks` | Quote لحساب ورمز وحدث زمني محددين، بعد التحقق من token | ملء صفقة / جودة سعر التنفيذ |
| `BTH1` | `OnTimer` كل نحو 1 ثانية | اتصال EA بالمقبس المحلي ووصول Heartbeat موقّع | حداثة Bid/Ask أو اتصال الوسيط |
| `BTE1` | إشارة `OnTradeTransaction` تُرسل بواسطة `OnTimer` | احتمال تغير حالة حساب؛ ضرورة فحص Snapshot/History من جديد | نجاح/رفض/حجم صفقة أو أمر قابل للتنفيذ |

الرسائل كلها تستخدم Token مؤقتاً مربوطاً بمجلد البيانات للمنصة، ولا تتضمن كلمات مرور أو أوامر تداول. `OnTradeTransaction` ينفذ زيادة عداد بسيطة فقط ولا يكتب في Pipe مباشرة لتجنب تعطيل طابور أحداث MT5 المحدود. لا نستنتج ترتيب التنفيذ من ترتيب وصول الأحداث.

عند `BTE1` صحيح ومطابق لرقم الحساب والرمز، يطلب Gateway تحديثاً كاملاً جديداً للمراكز والأوامر وتاريخ الوسيط. وصول `BTH1` وحده **لا** يضبط Quote freshness ولا يفتح صفقة.

### 3 — الاستقرار والمراقبة

- دورة Snapshot الكاملة للقناص 0.5 ثانية، وتقرير Deal PnL اليومي 5 ثوانٍ مستقلاً عن سجل المصالحة الحقيقي.
- فشل وحيد من MT5 API لا يسبب `shutdown()` إن كان `terminal_info` وحساب MT5 ما زالا صالحين، لكن لا يسمح باستخدام مراكز غير موثقة للتداول.
- أخطاء Core المحلية تُمنح مهلة محدودة للتعافي، مع حفظ نتيجة الإرسال الغامضة وعدم تكراره.
- **من إصدار EA 1.17 (مسار العزل أضيف في 1.16):** Gateway ينشئ `sniper.pipe` داخل `MQL5/Files/BrainTrade` يحتوي اسم Named Pipe فريداً مربوطاً بنفس token في `sniper.token`. يجب إعادة ترجمة **EA 1.16**؛ EA 1.15 القديمة لا تستطيع الاتصال بالـPipe العشوائي وتنتقل المنظومة تلقائياً إلى Poll دون الادعاء بأن Native متصل.
- إذا لم يوجد `sniper.pipe` عند تشغيل EA الجديدة فإنها تتعامل مع Gateway القديم ذي الـPipe الثابت للتوافق فقط. لا تخلط EA قديمة مع Gateway جديد في اختبار Native.
- يقوم Gateway بمسك قفل نظام تشغيل حصري مشتق من **MT5 data_path**، حتى لو اختلف مجلد BRAINTRADE الخاص بـCore. إذا كانت المنصة ملك Gateway آخر، يرفض الربط **قبل تنفيذ أوامر**. ينتهي القفل بإغلاق Gateway وبعد إنهاء تنظيف دفتر الإرسال؛ ملف القفل الباقي في مجلد temp ليس دليلاً على عملية نشطة.
- في حال وجود نسختين مختلفتين من MT5 لكل منهما مجلد بيانات مستقل، يستخدم كل Gateway اسم Pipe مختلفاً؛ لا يعودان يتعارضان على `BrainTradeSniperV1`.
- Token وملفات EA يجب أن تأتي من **نفس إصدار مصدر الفرع**. إصدار 1.17 يعرف رسائل `BT2/BTH1/BTE1` ولا يرسل أوامر تداول مباشرة.
- تم تحديد أقصى دفعة داخل `OnTick` إلى 32–128 Tick (افتراضياً 64)، وتستكمل `OnTimer` الدفعات المتبقية. تظل `FileFlush` موجودة على المسار السريع لتقليل التأخير، ويعرض EA أعلى زمن `FileFlush` و`OnTick` وعدد المرات البطيئة؛ لا يعني هذا ضمان عدم الحجب عند بطء نظام التشغيل.
- يسجل Gateway كل 30 ثانية `BRAINTRADE_LOCAL_LATENCY` في `gateway.log` مع P50/P95/P99 لزمن رد Core المحلي، ودورة Gateway، وتحديث Snapshot. هذه أزمنة **محلية** وليست وقت وصول الصفقة أو فتحها لدى الوسيط.
- بسبب وجود عمليات SQLite كبيرة متزامنة داخل Rust Core، **تُرفض عمليات Backup/Brain Export/Import والتصدير الثقيل أثناء START أو وجود مراكز/أوامر غير محسومة**. يستمر عمل STOP والإغلاق ومصالحة الوسيط. هذا تخفيف ضروري للاختناق ولا يحقق بعد عزل كل وظائف البحث عن خيط Core.
- `STOP` لا يعني إغلاق صفقات الوسيط ولا إنهاء المنصة؛ إنه يوقف الدخول وفق آلية Core.

### 4 — الاختبارات والقبول

للمراجعة الآلية: `tests/test_managed_mt5_terminal.py` و`tests/test_mt5_native_control_protocol.py`، واختبارات Python/Rust الحالية، واختبار Named Pipe الحقيقي وMetaEditor على Windows. صلاحية الكود على CI لا تثبت الربط لدى وسيط المستخدم.

لا يُعتبر المسار مستقرّاً تشغيلياً إلا بعد تشغيل النسخة على Windows متصلة بوسيط المستخدم، وتجربة نقل الحساب بين Demo وLive تحت STOP، فصل/استعادة الإنترنت، إزالة EA وإعادتها، إعادة تشغيل Gateway، والتحقق من:
- عدد إعادة تهيئة `MetaTrader5.initialize` وأسباب فشلها.
- معدل وصول BT2 والـHeartbeat ومدة انقطاعهما والـTick source time.
- التطابق الدائم بين `terminal_info.path/data_path` والمسار المضبوط.
- نتائج History/Deal وحجم المركز المتبقي بعد أي أمر؛ لا يُعتمد ACK وحده.
- عدم تكرار `order_send` وتوقف التنفيذ على الحساب غير المطابق.

## لماذا لا نضمّن `terminal64.exe` داخل ZIP؟

لأن ترخيص توزيع نسخة MetaTrader الخاصة بوسيطك يحتاج إذناً من الجهة التي توفرها، ولأن ملف EXE وحده لا يكفي. **البديل الأفضل**: التطبيق يدير نسخة رسمية مثبّتة مستقلة في مجلد معلوم، وتُحدّث المنصة من مصدرها المعتمد. لا يستخدم كود المشروع أي طريقة لتجاوز تسجيل الدخول أو شروط الوسيط.
