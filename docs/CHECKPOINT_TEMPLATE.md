# Checkpoint Template

Use this structure in `BUILD_HANDOFF.md` for every meaningful development checkpoint.

## Active task

Describe one exact task.

## Acceptance condition

State what must be true before the task can be considered complete.

## Changed files/modules

List the files or modules actually changed.

## Verification

- `PASS` — command/test actually passed.
- `FAIL` — command/test actually failed.
- `NOT RUN` — not executed.
- `BLOCKED` — unavailable in the current environment.

Record exact commands where practical.

## Known incomplete work

Write anything intentionally left unfinished or risky.

## Next exact action

One concrete next step that another session can execute without guessing.
