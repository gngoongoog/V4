# BRAINTRADE V25 — G6-H | تطبيق ساعة قبول Broker داخل محرك التعلّم نفسه

## الثغرة التي أغلقناها

في G6-G أنشأنا جدول `coordinator_broker_admissions` الذي يوثق أول لحظة Core حفظ فيها عينة MT5 Demo مكتملة، مع بصمة SHA-256، لكن محرك `coordinator_learning.rs` ظل يستخدم `closed_ms` الأصلي لاختيار عينات `broker_stats` و`contextual_stats`. عندما يستورد النظام تاريخ وسيط متأخراً، يمكن لقرار قديم معاد حسابه أن يرى عينة أُغلقت سابقاً لكنها **لم تصل إلى Core إلا لاحقاً**.

## إصلاح التنفيذ لا التقرير فقط

في G6-H عدلنا مساري:
- `broker_stats`: الإحصاء الفعلي الذي يتحكم في وزن Coordinator.
- `contextual_stats`: سجل الأخطاء والخسائر المتكررة الذي يؤثر في تفضيل العقل.

صارت كل قراءة تفحص، بالإضافة لمتطلبات G6-F للهوية وعمولة MT5 وصحة Reward، ارتباط صف Broker بإيصال `coordinator_broker_admissions` مطابق **للمصدر والمركز** وتتحقق من:
1. `admitted_ms >= closed_ms` و`admitted_ms <= now` الخاص بدورة قرار Core.
2. تطابق `context` و`brain` و`closed_ms` بين إيصال القبول وصف العينة المخزّن.
3. البروتوكول المعلن `g6g-runtime-same-transaction-v1`.
4. تطابق SHA-256 لنص صف التعلم الحالي مع النص الأصلي المثبت عند أول قبول.

أي صف بلا إيصال G6-G أصلي، أو ببيانات مغايرة، أو بتاريخ قبول مستقبلي بالنسبة للقرار، يبقى في قاعدة SQLite لكنه **لا يدخل التعلّم الجديد** ولا ذاكرة الأخطاء في هاتين الدالتين. لا نخترع توقيت قبول تاريخي للنسخ القديمة. هذا قد يخفض مؤقتاً بعض أعداد العينات/الأوزان بالمقارنة مع إصدار G6-F، وهو تصحيح بيانات موثوقيتها وليس حذفاً لصفقات أو أموال.

## لماذا هذا مهم للتحقق الاقتصادي؟

عندما نريد تقييم نسخة العقول وقت `T` يجب ألا تستعمل نتيجة وصلتنا عند `T+1` حتى لو كان الوسيط سجل الإغلاق عند `T-1`. G6-H يفرض هذا في نفس القرار بدلاً من الاكتفاء بتنبيه تقرير G6-G لاحقاً.

**لا يشمل هذا التغيير محركات Sniper وStudent المستقلة؛ تحتاجان بوابات قبول زمنية منفصلة** قبل إمكان اعتماد كل النظام على سجل موحّد. لا ندعي اكتمالها.

## الاختبارات

الاختبارات الحقيقية في Rust تتحقق من الإيصالات المفقودة، العينة المقبولة بعد وقت القرار، وتغيير صافي نتيجة محفوظة بعد القبول، وعدم تسرّبها إلى الوزن أو ذاكرة الخسائر. اختبارات المشروع القديمة تستخدم قبولاً اصطناعياً صريحاً لعينة Fixture، ولا تضع بيانات سرية ولا تتصل بوسيط.

يتطلب اعتماد المرحلة نجاح `cargo test --locked -p braintrade-domain -p braintrade-runtime`، وResearch وWindows وPortable على **آخر SHA**.

## ما الذي لا يثبته؟

هذه ساعة تطبيق **محلية**: لا توجد شهادة زمنية خارجية، ولا سجل أحداث غير قابل للتلاعب، ولا تجميد مستقل لـAdaptive، ولا مقارنة MT5 Broker بين ذراعين منفذين. لا يُسمح استخدامها كإثبات ربحية OOS أو كترخيص تلقائي لحساب REAL أو تغيير مستويات المخاطرة.

المشروع ما زال يحتاج تجميع بيانات Demo مستقبلية وفحص التنفيذ الفعلي خارج عينات التدريب.
