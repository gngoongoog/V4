# BRAINTRADE V25 — G5-F | Student Exit Learning لا يقبل عينات MT5 مزوّرة

## الخلل المؤثر على التعلم المكتشف بعد G5-E

كان Student Exit Learner يقرأ بشكل مستقل أول صف من coordinator_broker_samples بحسب command_id وbrain وcontext، ويضع payload مباشرة داخل Experience.actual من دون التحقق من الحسابات المالية أو مكافأة الصفقة أو اتصالها بالمركز الفعلي. لذلك نتيجة مخزنة فيها net سلبي لكنها فاقدة العمولة أو تحمل reward مزوّراً قد تطلق record_loss في سياسة خروج Student، حتى وإن رفضت وحدة Coordinator/Expert/Sniper تلك العينة.

كما كانت بعض Experiences المخزنة قبل ترقية G5-E تستطيع إعادة تحميل actual غير متحقق عبر Student.load.

## التعديل
- عند قبول نتيجة Broker جديدة، يشترط تطابق DB position_id مع المركز الفعلي للتجربة، وتطابق payload.position_id معهما.
- كل عينة تمر بالدالة المشتركة verified_broker_feedback التي تتحقق من booked gross, commission, swap, fee, net, net_per_lot, risk_money, r_multiple, reward_v2.
- إذا فشلت العينة تُترك SQLite الأصلية بلا حذف وتُستبعد من Student actual ومراجعة الأخطاء والدراسة الورقية؛ لا يوجد تعويض مجهول للعمولة ولا صفقة مزيفة.
- Student.load يعيد فحص أي Experience.actual قديم قبل استئناف مسار الدراسة. الملفات القديمة لا تُحذف، ولا يُدّعى إصلاح أثر محتمل سبق تخزينه داخل سجل سياسات تاريخي من دون إعادة بناء مستقل.
- سجلات تاريخ الصفقات والشارت والتعلّم الأصلية تبقى محفوظة. لا تغيير في API أو المخاطر أو تنفيذ أوامر Broker أو مرونة الحسابات الصغيرة.
- بعد تصحيح صف ناقص في Broker يمكن قراءة النتيجة المكتملة، لكن لا يُعاد وصف مسار أسعار ورقي سابق وغير موثوق بأنه صالح.

## الاختبار
- test g5f_student_never_converts_fake_mt5_reward_into_real_loss_memory: صف MT5 سلبي ذو تكاليف مكتملة لكن reward مزوّر لا يدخل actual ولا يضيف خسارة تدريبية. ثم يعاد reward الصحيح ويُقرأ فقط الإثبات الحقيقي مع بقاء التجربة السابقة غير مؤهلة.
- تحديث عينات اختبارات Student القديمة لتحتوي بيانات MT5 مكتملة بدلاً من استخدام net وحده.
- بوابات القبول: Research/Windows/Linux/Portable على SHA النهائي، واختبار MT5 Demo Native لاحقاً على جهاز المستخدم.

## التقييم
هذا إثبات نزاهة مسار تحديث Student وليس برهان فعالية اقتصادية لأي استراتيجية. سياسة المتعلم الورقية لا تتحول إلى PnL وسيط أو نموذج Live تلقائياً. تبقى المقارنة OOS الحقيقية وموافقة المستخدم منفصلة.
