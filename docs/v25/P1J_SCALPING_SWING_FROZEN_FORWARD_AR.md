# BRAINTRADE V25 — P1-J: تثبيت سياسات Scalping/Swing ومقارنتها المستقبلية

**التاريخ:** 2026-10-24  
**النوع:** دراسة بحثية للقرارات فقط، لا تنفّذ MT5 ولا تدرّب العقول.

## أين توقف P1-I؟
- P1-I أصلح صدقية نتائج **Expert المجمّدة الورقية**: الأزواج المؤهلة لوصف الأداء تتطلب مسار أسعار مراقباً وفحص عقد تداول تقديرياً؛ النتائج ليست fills.
- P1-H يعرض إغلاقات Demo التاريخية للأوضاع الأربعة، **ولا** يثبت OOS مستقلاً.
- P1-J يوسّع **نفس عقد سياسة المنسق المجمدة المستقبلية** إلى **Scalping وSwing**؛ لا يُنتج عائداً افتراضياً لهذين الوضعين لغياب محاكي يطابق كل المراحل.

## ما تم تنفيذه فعلياً
1. `frozen_coordinator.rs`: Snapshot مستقل لكل `context + trading_mode` من Demo. تُجمَّد إعدادات الحساب والرمز، عضوية العقول، أوزانها، جينوماتها، ومعلومات الخروج. سجل Snapshot محمي من إعادة الكتابة؛ التسجيل الحالي يبقى واحداً لكل mode/account وتستطيع تجميد وضع آخر دون إلغاء الأول.
2. `observe` يسجل **قرار المنسق المجمد مقابل القرار الحالي** فقط عند رصد **شمعة M1 مكتملة حديثة** بدأت بعد التجميد، ولا يسترجع الشموع الماضية؛ والمفتاح `run_id + bar_time` يمنع المضاعفة. كل دورة تتطلب Demo، وحساباً ورمزاً مطابقين والوضع المختار عينه. التقييم مستقل عن سجل أوامر الوسيط.
3. `stop(db, context, mode)` يعطل **تسجيل قرارات جديدة في وضع واحد** دون إيقاف تجربة وضع آخر، أو تغيير START/STOP أو حالة الأوامر، أو إعادة كتابة السجلات.
4. `report(db, context, mode)` يُعيد وضع وسياق النتيجة صراحةً، ونسب توافق القرار/اختلافه والأزواج الجاهزة؛ **Expert فقط** يملك `paired_quote_paper`، أما Scalping/Swing فتعود `null` ولا يتم تصنيع أرباح.
5. الحفاظ على توافق **Snapshots Expert السابقة** التي لم يكن فيها حقل `mode` الإضافي: يتم قبولها فقط إذا تطابق الوضع الموجود فعلياً داخل `config` المحفوظ.
6. مسار Core وTauri `/v1/execution/frozen-coordinator` يستقبل `freeze/stop` مع `mode` صريح: **expert/scalping/swing فقط**. شروط STOPPED، تسوية أوامر الوسيط، Demo متصل، الحساب والرمز والوضع المطابق محفوظة وتُتحقق في Core أيضاً.
7. نافذة Windows `Brain Control Room` تدعم تبديل العرض والتجميد حسب الوضع، وتحجب أي أرقام من وضع/حساب سابق. تعرض حالة وعينات **القرارات** في Scalping/Swing، وتحافظ على قسم Paper لـExpert وحده.
8. **Sniper صراحة خارج نطاق تجربة M1**: Fast Pulse القناص يستخدم تيكات ومساراً زمنياً مختلفاً، ولا يُسمح باستعمال إغلاق شمعة بدلاً عنه. يعرض Core `tick_native_research_not_implemented` ولا ينفذ `freeze` لهذا الوضع.

## حدود النزاهة
- هذا ليس مقارنة متزامنة بين الأوضاع الثلاثة على نفس نافذة السوق، ولا يعني إثبات تداول سببي خال من كل تسرب للبيانات: السياسة مجمّدة لكل وضع على حدة، لكن العيّنات تتوقف على اختيار المستخدم لهذا الوضع ووجود شموع مكتملة حديثة.
- لا توجد **نتائج PnL تجريبية أو حقيقية** لـScalping/Swing في هذا المسار. لا توجد محاكاة مستقلة كاملة للأوامر، تأخر التنفيذ، تبعيات الـPortfolio، الإغلاق وعمولة الوسيط.
- عدد الشموع والتوافق مع الإشارات هو دليل قرار فقط، **ليس win-rate** ولا تجربة forward **مستقلة OOS كاملة**.
- Sniper Tick-specific ما زال مطلوباً كمرحلة لاحقة مستقلة. لا نجمع نتائجه مع شموع M1.
- اختبارات Windows WebView2 اليدوية وتشغيل MetaTrader 5 Demo وإثبات الرسوم والتنفيذ ما زالت `NOT TESTED` إلى حين توفر جهاز.

## الاختبارات المطلوبة
- `cargo test --locked -p braintrade-runtime frozen_coordinator::tests`: التجميد من وضعين مختلفين، فصل القرارات، عدم تكرار الشمعة، إيقاف وضع دون الثاني، رفض Sniper، عزل الحساب والرمز، التوافق الرجعي Expert.
- `npm --prefix apps/terminal test`: بطاقة الأوضاع وتغيير الحساب ومنع مكاسب Expert الورقية من التسرب إلى Scalping/Swing.
- `python3 -m unittest discover -s tests -v`: سلامة فحص الـ22 صفحة وجرد Tauri IPC.
- Windows Portable/Linux CI **على نفس Commit النهائي**؛ لا يساوي اختبارات MT5 اليدوية.

## الخطوة التالية
**P1-K مقترحة:** مسار Tick مرصود مستقل وسياسة Sniper مجمّدة تُقاس مقابل نفس تيكات المستقبل بدون تاريخ مسرّب، مع التحقق من فقدان تيكات Native/HTTP وقواعد عدم استنتاج النتائج عند فجوات. بعد ذلك فقط يمكن التفكير بمقارنة زمنية مشتركة؛ ولا تُدمج مع Paper Expert أو تاريخ Demo عند تقييم الربحية.
