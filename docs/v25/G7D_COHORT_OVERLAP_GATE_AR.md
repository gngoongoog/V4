# BRAINTRADE V25 — G7-D | منع تضارب الدراسات ونسب الصفقات مرتين

**المجال:** Expert / Scalping / Swing، تسجيل القرارات المزدوجة لـ Frozen / Adaptive المكتملة على M1. المقارنة بحثية ولا تفتح أي صفقة MT5 جديدة.

## ماذا نفذنا؟

أضفنا ملف `scripts/g7_cohort_overlap_gate.py` يعمل فوق سجل G7-A الأصلي وبصماته، ويقوم بفحص الدراسة قبل أن ينشر `g7_full_intent_census.py` أي نسبة تغطية أو صافي صفقات.

1. يفحص تسلسل تسجيلات `g7_pair_registrations` لكل **حساب/رمز/وضع**. يمنع دراستين نشطتين معاً لنفس الحساب والوضع، أو تسجيلين متضاربين في الوقت ذاته.
2. يفحص كل صف قرار M1: يجب أن تبدأ الشمعة **بعد** التسجيل، وتكون قد أغلقت قبل رصد القرار، وألّا يتأخر الرصد أكثر من مهلة 80 ثانية المنصوص عليها في مسار Rust. ويرفض قراراً بعد تسجيل دراسة أحدث لنفس الحساب والوضع؛ لا تجوز إعادة نسبه إلى دراسة قديمة.
3. يرفض أن تحسب الشمعة نفسها مرتين في دراستين من الوضع نفسه. وينبّه إلى محاولة تسجيل الوضعين المختلفين على نفس الحساب ونفس دورة الرصد.
4. يفحص مرشحي الربط بين قرار Adaptive والأمر الحقيقي عندما تتوفر `broker_commands`: يربط **كامل الإشارة** بنفس وقت Core، سياق الحساب، الوضع وهدف Demo، ويرفض نسبة الأمر نفسه لأكثر من زوج دراسي.
5. يمنع اعتبار نتيجتي تعلم `system` مسجلتين لمركز MT5 فيزيائي واحد كصفقتين مستقلتين.
6. التقرير الناتج يظل `inconclusive` حتى لو كان `overlap_gate=locally_consistent`، لأن الاتساق المحلي لا يعني ربحية أو جاهزية REAL.

## المسار التنفيذي الذي تغير

`scripts/g7_full_intent_census.py` يستدعي بوابة G7-D قبل حساب نسب المطابقة والإغلاق. عند أي تعارض تخرج الأداة برسالة خطأ ولا تعطي تقريراً يبدو سليماً، ولا تخفي الصفوف المخالفة. ويستمر تدقيق G7-A لمصدر الأحداث، وتدقيق G7-B لصفقات Broker ذات الرسوم الصحيحة.

## تشغيل الأداة

```powershell
python scripts/g7_cohort_overlap_gate.py --db "C:\path\to\actual\core.sqlite" --output "g7-d-integrity.json"
python scripts/g7_full_intent_census.py --db "C:\path\to\actual\core.sqlite" --output "g7-census.json"
```

استبدل مسار SQLite بمكان ملف Core **الحقيقي**. `mode=ro` يعني قراءة فقط؛ لا تعديل بالقاعدة أو أوامر MT5. لا تكتب النتيجة فوق ملف تقرير سابق.

## اختبار

```bash
python -m unittest discover -s tests -p 'test_g7_cohort_overlap_gate.py' -v
```

تختبر الحالات: تسجيلين متتاليين صالحين، تداخل زمن الدراسة القديمة بالجديدة، تسجيلين بنفس الساعة، دراستين نشطتين، حالتي وضع بنفس الشمعة/دورة الرصد، إفساد دليل محلي، اختلاف ساعة الاختبار، وصفين لعقل `system` ينسبان الربح لنفس مركز Broker. وعند نجاح الفحص لا يجوز تحويل `overlap_gate` إلى شهادة ربح أو نسبة تعلم.

## حدود مهمة

- إذا عدّل صاحب الجهاز **جميع** سجلات SQLite والبصمات والساعات في وقت واحد، هذه الأدوات لا تمتلك جهة توقيع خارجية لكشف ذلك بشكل مضمون.
- توقف الدراسة `active=0` لا يحتفظ حالياً بوقت إيقاف منفصل؛ نعتمد تسجيل الدراسة الجديدة وحدود كل قرار محفوظ، ولا نزعم إثبات كل فترة توقف.
- الفحص يغطي مراكز وأوامر Core المسجلة، وليس جميع صفقات MT5 اليدوية.
- Frozen ذراع قرار افتراضي **غير منفذ**؛ لا يوجد A/B Broker حقيقي بين Frozen وAdaptive.
- لا تعديل على مخاطرة المستخدم، اللوت، تداول REAL، التدريب أو الواجهة. لا دمج تلقائي على `main`.

## المتبقي بعد G7-D

ضبط تعريف بروتوكول الاختبار المستقبلي بشكل يفصل عن الأوامر التنفيذية الحالية، ثم تشغيل Demo فعلي على Windows وMT5 ومقارنة استقلالية/اتساق البيانات على عيّنات خارج التدريب. مراجعة فشل `smoke_core.py` السابق مطلوبة كقاطع بناء قبل الدمج.
