# BRAINTRADE V25 — G7-E | تقييم Holdout مسجل مسبقاً مع عدم اليقين

## الهدف

لا يكفي نجاح بناء Windows أو اختبارات Core لإثبات أن Adaptive مربح أو أن التعلّم أفضل من نسخة Frozen. مرحلة G7-E تضيف **تسجيل دراسة مستقبلية مسبقاً** و**تقريراً وصفياً محدود الصلاحيات** داخل `scripts/g7_holdout_report.py`، بالاعتماد على أدلة G7-A/B/C/D المحلية.

**لن يتحول نجاح أي شرط إلى موافقة LIVE أو استبدال آلي لنموذج تداول.**

## 1. تسجيل الدراسة قبل أول قرار

بعد بدء دراسة G7 من واجهة Frozen Coordinator، وقبل وصول أول شمعة قرار مستقبلية في تلك الدراسة، أنشئ ملف manifest:

```powershell
python scripts/g7_holdout_report.py register \
  --db "C:\actual\path\core.sqlite" \
  --run-id "THE_REAL_FROZEN_RUN_ID" \
  --source-commit "YOUR_EXACT_40_DIGIT_GIT_COMMIT_SHA" \
  --training-cutoff-ms 1790000000000 \
  --holdout-start-ms 1790100000000 \
  --holdout-end-ms 1790700000000 \
  --output "g7-e-registration.json"
```

الأرقام والمسارات ومعرف الدراسة **أمثلة توضيحية وليست مواعيد جاهزة**. حدّد وقت البداية والنهاية في المستقبل على أساس بيانات حقيقية، واحسب Unix milliseconds بدقة قبل التشغيل. مكوّن التسجيل يرفض وجود أي قرار مسجل مسبقاً في نفس الدراسة. ويشترط بدء Holdout بعد تسجيل الملف بمهلة لا تقل عن 60 ثانية، وأن يكون حد التدريب أقدم من تاريخ إنشاء الدراسة، وأن تكون بصمة Snapshot مطابقة لقاعدة Core. يحتفظ ببصمة SHA-256 للمحتوى؛ لا يسمح بالكتابة فوق التسجيل السابق.

**مهم:** ملف JSON وتوقيته مصدرهما جهاز المشغّل. هذه ليست جهة ختم زمن مستقلة ولا ختم توقيع غير قابل للتلاعب. احفظ الملف كما هو خارج جهاز الدراسة إذا كنت تحتاج أرشيفاً مستقلاً؛ أداة G7-E وحدها لا تقوم بذلك.

## 2. استخراج التقرير

بعد بدء الدراسة، أو بعد انتهائها:

```powershell
python scripts/g7_holdout_report.py audit \
  --db "C:\actual\path\core.sqlite" \
  --manifest "g7-e-registration.json" \
  --output "g7-e-report.json"
```

يُفتح ملف Core `mode=ro` في معاملة قراءة واحدة، ولا تُرسل أي أوامر MT5. وينفذ كل فحوص G7-A وG7-B وG7-C وG7-D قبل استخراج النتائج.

## 3. من يدخل بالنتائج؟

- تؤخذ كل أوامر فتح `system` الخاصة **بنفس حساب/رمز/وضع الدراسة** خلال `holdout_start_ms <= created_ms < holdout_end_ms`، ما دام وضع التنفيذ `Demo` وسجلات الهوية صحيحة.
- حتى تدخل النتيجة في أرباح الوسيط، يلزم أن يكون أمرها مطابقاً بالضبط لقرار Adaptive المستقبلي، وأن يثبت معرّف المركز وصفقة الدخول واتجاهها و`magic`، وأن يكون حجم الخروج **مغلقاً بالكامل**.
- يجب أن تكون `profit` و`commission` و`swap` و`fee` كاملة ومتطابقة مع دفتر `broker_deals`، وأن تكون النتيجة قد قُبلت محلياً في Core قبل نهاية Holdout.
- الصفقة المفتوحة أو المرفوضة أو الناقصة **لا تُحذف من مقام الأوامر المؤهلة**، ولا يُختلق لها فوز أو خسارة أو نتيجة صفرية.
- إذا جاءت نتيجة Broker أو سجل اعتمادها **بعد انتهاء** الفترة المسجلة، لا نضمّها إلى المجموعة بقرار لاحق. لا يجوز تحسين النتيجة باختيار نهاية مختلفة بعد معرفة الأرباح.
- تفحص الأداة `coordinator_broker_admissions` لترصد دخول عينات جديدة إلى دفتر التعلّم بعد التاريخ المحدد كحد تدريب. وجود تلك العينات علامة صريحة إلى أن سياسة Adaptive قد تغيرت أثناء التقييم. غيابها أيضاً **ليس دليلاً** على توقف بقية مسارات التعلّم.

## 4. كيف نفهم الإحصائيات؟

- `complete_broker_outcome_coverage`: عدد مراكز Demo المغلقة المقبولة / عدد أوامر الفتح المؤهلة. **ليست نسبة نجاح التداول**.
- `verified_closed_win_rate`: نسبة الصفقات الرابحة داخل المجموعة المغلقة المقبولة فقط؛ لا تشمل النتائج المفقودة أو المراكز المفتوحة.
- `verified_closed_win_rate_wilson_95_descriptive`: فترة Wilson الوصفية لنسبة الربح ضمن **مجموعة الصفقات المغلقة المختارة**؛ لا تزيل أثر انحياز اختيار الصفقات أو ترابط الزمن.
- `daily_cluster_bootstrap_mean_net_r_95_descriptive`: Bootstrap قطعي بحسب اليوم لمتوسط R، يُحسب فقط عندما تتوفر نتائج مغلقة في 5 أيام UTC على الأقل. يستخدم بذرة ثابتة مشتقة من بصمة manifest لإعادة إنتاج النتيجة؛ لا يعامل الثقة الوصفية كبرهان سببي.
- الحد الأدنى المبرمج للمراجعة الوصفية **30 صفقة مكتملة و5 أيام UTC**، بالإضافة إلى التغطية، وغياب نتائج منسوبة خارج المجموعة، وعدم وجود قبول عينات Broker جديدة بعد الحد المصرح للتدريب. **حتى مع تحقيقه** تظل النتيجة `observational_descriptive_only`، وليست `pass` أو تفوقاً مثبتاً.
- `frozen_broker_pnl = null` و`paired_broker_delta = null`: Frozen لم ينفذ صفقات فعلية، فلا يجوز منح ذراع غير منفّذ أرباحاً حقيقية أو افتراض أنه خسر أمام Adaptive.

## 5. شروط القبول الواقعية

تقييم G7-E هو أداة **نزاهة بيانات** أكثر منه إثبات فاعلية استراتيجية. وللدعوى الأقوى عن تفوق التعلم يجب على الأقل: اختبار على Windows وMT5 Demo واقعی، فصل زمني/خارجي قابل للتحقق بين بيانات التدريب والاختبار، تثبيت فعلي للسياسات أو بروتوكول online-learning مُصرّح مسبقاً مع إثبات زمني مستقل، معالجة الانقطاعات والصفقات غير المغلقة، ووجود مقارنة عادلة قابلة للتنفيذ.

