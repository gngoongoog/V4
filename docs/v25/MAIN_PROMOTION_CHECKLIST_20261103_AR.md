# BRAINTRADE V4 Enterprise V25 — قرار اعتماد فرع main
**التاريخ:** 2026-11-03  
**الفئة:** مصدر Windows الرئيسي بعد اجتياز اختبار المصدر والواجهة، **وليس شهادة تشغيل أموال حقيقية**.

## ما الذي يمكن اعتماده برمجياً
- Rust Core + Python Gateway + Tauri/React وواجهة Concept4 ونظام STOP/START، مع اختيار المستخدم **Demo أو Live**؛ اختيار الحساب لا يرسل أمر ولا يغير كلمة سر MT5 أو حسابه بصمت.
- حفظ ومراجعة إعدادات القناص والمخاطر والعمولة مع بقاء أوامر الوسيط والمصالحة والحسابات معزولة.
- فحوص G7، واجهة Concept4، إغلاق العمليات، واختبارات Cargo وPython على **Commit الدمج الفعلي**، بالإضافة إلى بناء Windows محمول من ذلك المصدر ذاته.
- حساب مخاطرة افتراضي بحد **2%** (تكلفة الوقف المقدرة تشمل العمولة والانزلاق؛ وليست خسارة مضمونة). يسمح للمشغل برفع الحد إلى **5%** عبر خيار `live_elevated_risk_opt_in` المستقل على Live؛ موافقة Demo لا تعمل على Live، والعكس. يبقى فحص الهامش واللوت والعقود والتأكيد النهائي في Gateway. وضع Micro REAL المؤقت منفصل، وSTOP لا يصفّي المراكز تلقائياً.

## حدود مثبتة لم تكتمل بعد — لا تخفها عن المستخدم
1. **TP1/TP2/TP3 التلقائي:** كود حجز الخطة وتحليل مستوياتها وسجل التسوية البحثي موجود، لكن `incomplete_tp_stage_execution_locked` يرفض التفويض النهائي لأوامر TP المرحلية. لا تعتبر `reserved_not_dispatched` صفقة، ولا تنفذ إغلاقاً جزئياً اعتماداً على مسودة. يتطلب الإكمال منتج `broker_commands` ذرّي وقواعد فحص ما قبل الإرسال، وتسوية MT5 Deals وإثبات الحجم المتبقي، ومنع الإرسال المكرر بعد crash/restart، ثم تفعيل TP2/TP3 وBreakeven وفق إثبات المرحلة الأولى فقط.
2. **اختبار الوسيط الحقيقي:** لا توجد شهادة E2E على جهاز المستخدم لربط EA وإرسال/استرجاع أوامر MT5، أو إثبات أن `.mq5` تُرجم إلى `.ex5` وقام بإرسال ticks فعلياً.
3. **إحصاء الربحية:** لا توجد أدلة صافية مثبتة على أفضلية مالية حقيقية بعد السبريد والعمولة والتمويل والانزلاق ورفض الأوامر. نتائج Shadow/Backtest/Research لا تساوي نتائج Live.
4. **بعض التجارب البحثية Demo-only:** تجميد عقول بحثية أو عينات التعلم القديمة يقبل Demo عمداً لأسباب صحة الدليل العلمي. هذا لا يمنع ربط الحساب Live أو التداول الأساسي، ولا يعني أن أبحاث Demo تستحق ترقية آلية لحساب حقيقي.
5. **الواجهة ومناوبات جهاز المستخدم:** اختبارات headless وWebView لا تحل محل اختبار كل زر وتدفق تسجيل الدخول والخروج وملفات Python على جهاز Windows الفعلي.

## شرط الدمج إلى main
- جميع فحوص CI الإلزامية على رأس الفرع الحالي **SUCCESS**. إذا ظهر أي فشل يعالج قبل الدمج ولا نستخدم نتيجة Commit أقدم.
- بناء Windows ZIP من نفس مصدر Git، التحقق من SHA256SUMS وEXE والبنية الأساسية، وعدم اعتماد أثر يحمل Commit مؤقت مختلف على أنه HEAD الفرع.
- يمكن اعتماد **main كخط أساس V25 محدث وقابل للاختبار** فقط بشرط بقاء TP التلقائي غير مسلح والحدود السابقة معلنة. **لا يساوي ذلك Live production approval.**
- أي توسعة TP التلقائي أو ترقية أبحاث إلى فتح صفقات Live تتم لاحقاً على فرع مستقل، مع اختبارات عودة، ثم PR منفصل ومراجعة broker acceptance.

## اختبار القبول المقترح على Windows
1. انسخ مجلدك القديم وخذ Backup؛ فك ZIP جديد بالكامل، وشغّل `BrainTradeNext.exe`. افتح `VERIFY_SYSTEM.cmd`.
2. تحقّق من ربط Demo ثم Live **بشكل مستقل** مع MT5 وعلى حسابين مصرحين، ومن تطابق `MT5` و`Core` في الشريط العلوي؛ لا تستخدم أموالاً حقيقية لإثبات وظيفة جديدة غير مختبرة.
3. افحص عمل START/STOP وحفظ وتحديث القناص وتلقي ticks والـNamed Pipe؛ يجب ألا يبقى `WAITING` بعد الربط.
4. نفّذ صفقة اختبار Demo صغيرة عمداً (إن كانت مناسبة) وتأكد من دورة `queued -> dispatched -> placed/filled -> observed` من MT5 Deals والمصالحة؛ لا تفترض التنفيذ من toast الواجهة.
5. تأكد من الإغلاق الكامل وإيقاف العمليات التابعة بدون تعطيل MT5 الخارجي، ومن إعادة التشغيل وتطابق الحفظ والنسخ الاحتياطية.
6. راجع عمولة كل 1 لوت (7 لكل لوت = 0.07 لكل 0.01)، السبريد اللحظي، قيمة pip بحسب الرمز، وانزلاق السعر قبل تقييم أي نتيجة مالية.

**معيار الأدلة:** نتائج CI والملفات يمكن مراجعتها، أما اختبارات الوسيط الحقيقي فلا تُنسب للنظام ما لم يقدَّم سجل MT5 الفعلي.
