# BRAINTRADE V25 — G4-B: حالة قاطع الخسارة اليومية وميزانية المخاطرة في Windows

## المهمة
تحويل صفحة المخاطر إلى عرض تشغيلي لحالة قاطع الخسارة الفعلية من Rust Core، لا مجرد JSON. يشمل ذلك حالة Core اليومية لجميع الرموز، حدود المستخدم، المبلغ المتبقي تقديرياً قبل بلوغ سقف الخسارة، وسجل القفل اليومي.

## المصدر والقيود
- مصدر البيانات حصراً GET /v1/risk/monitor بعد مطابقة account/server/currency/DEMO/REAL عبر شهادة microAttestation الحالية وحداثة observed_ms حتى 15 ثانية.
- `remaining = max(0, allowed_day_loss - estimated_day_loss)` **تقدير للعرض**. لا يمثل ترخيصاً بفتح صفقة ولا يلغي فحوص Core/MT5.
- إذا كان القاطع `disabled`، لا يُعرض مبلغ متبقٍ وكأنه سقف نافذ. إذا وجد قفل سابق، تُعرض رسالة صريحة بأن قفل اليوم باقٍ في قاعدة Core.
- إذا كان `locked` مع نقص في بيانات الحساب اليومي، تظهر حالة القفل المثبتة لكن كل الأرقام المالية غير المكتملة تصبح شرطات.
- إذا عُدّت حالة `ready` مع بيانات غير متاحة أو حالة `disabled` مع `enabled=true` يرفض العارض اعتماد التقرير ويُخفي الأرقام.
- لا تتغير سياسة المخاطر ولا الخيارات المرتبطة بحساب 50/100 دولار واللوت والرافعة. الغرض توفير شفافية حسابية قابلة للتحقق.

## الفحوص
اختبار Node يتحقق من اليوم القابل للاعتماد، قفل سابق، تجاوز الحد، تعطيل المستخدم، غياب الأرقام، التباس نوع الحساب، التأخير، هوية Core، وقيم اليوم الغريبة؛ وينظر إلى وجود المكوّن في واجهة Risk. تبقى تجربة WebView2 وMT5 Demo على Windows مستقلة عن بوابات CI.

G4-B فرع فوق G4-A؛ main وEnterprise V24 بلا تغيير.
