# BRAINTRADE Enterprise V25 — P1-K2: مصدر التيكات المقبولة واستمرارية رصد القناص

## الحالة عند بدء العمل
- فرع V25 الفعلي انتقل بعد P1-J إلى **P1-K1**، آخر SHA قبل هذه المرحلة: `890992a9da9a7f651eeff7f2aaad8531ec316bc7`. بوابات GitHub على نفس SHA: **P0-O Windows/Linux Portable وP1-A وP1-B وP1-C وجورنال التنفيذ SUCCESS**.
- P1-K1 أصلح `source_quote_time_ms` وتفريق ساعة الوسيط عن مفتاح ترتيب الحدث. هذا أساس منطقي مهم لكنه ليس مراقبة اكتمال تيكات Native/Poll.
- التجميد المستقبلي لقرارات Expert/Scalping/Swing موجود. **Sniper لا يملك Frozen tick-policy trial حتى الآن**؛ لا نستخدم M1 في القناص.

## المنفذ في P1-K2
1. **Gateway**: كل Pulse حديث يصرح `quote_source: native | poll` من الفرع الفعلي الذي التقط السعر، مع `native_dropped_total` عداد امتلاء طابور Native داخل عملية Gateway. الوقت الأصلي للوسيط والمفتاح الاصطناعي موجودان من P1-K1. رسائل Gateway القديمة تبقى قابلة للقراءة لكن مصدرها `unknown`.
2. **Rust FastContext**: يرفض `quote_source` غير صريح من القيمتين، أو مصدر Native/Poll مصرح عنه بلا وقت وسيط أصلي أو بلا عداد Native. لا يسقط البيانات التي يرسلها Gateway القديم دون مصدر، لكنه لا يسميها بيانات Native مؤكدة.
3. **Rust Audit**: سجل مراقبة خفيف في الذاكرة على التيكات التي **قبلها Fast Pulse ونجح طلبها** فقط؛ لا SQLite كتابة على المسار السريع، ولا يحتسب طلبات مرفوضة. مفصول بحسب سياق الحساب `server/login/symbol/currency` ويرفض التقرير على REAL أو عند فقد جلسة صالحة.
4. المؤشرات الوصفية: عدد رسائل Native المقبولة، Poll المقبولة، مجهولة المصدر، تغيّرات المصدر، فواصل زمن الوسيط فوق 1.5 ثانية، أعلى فجوة مرصودة، وتغيّرات ضمن الملي ثانية نفسها، وزيادة عداد امتلاء Native منذ **أول رقم ملحوظ** لهذه الجلسة. عداد Native شامل للعملية؛ الرقم التاريخي السابق للخط الأساس لا ينسب للحساب، وعودة العداد للخلف تظهر `native_mailbox_counter_resets`.
5. التقرير `GET /v1/execution/sniper-tick-audit` محمي بعزل الحساب/رمز التداول، DEMO، Core Session حديثة، ووضع Sniper. أضيف إلى قائمة قراءة Tauri فقط. بطاقة Sniper في Windows تعرض المؤشرات الحية مع `ScopedReadFence` وتخفي الأرقام عند REAL أو تبديل الحساب أو نهاية حداثة آخر قبول.
6. **لا تغييرات على الربح، أوزان العقول، قواطع المخاطرة، أو MT5 order_send**. لا يتم تجميد أو تشغيل سياسة بحث للقناص بهذه المرحلة.

## ما لا يمكن استنتاجه
- `accepted_pulses` **لا يمثل العدد الحقيقي لجميع تيكات الوسيط**. بين مصدرين مقبولين قد توجد أسعار كثيرة لم يرها Core. لذلك `observed_market_tick_count=null` و`estimated_missing_market_ticks=null` دائماً، و`broker_tick_delivery_complete=false`.
- `observed_quote_gaps_gt_1500ms` يحصي الفواصل المرصودة فقط، وقد يعني سوقاً هادئاً أو انقطاع مصدر أو تأخر النقل؛ ليس دليلاً مستقلاً على فقد تيكات.
- عدّاد Overflow يعني فقداً في **طابور Gateway Native** بعد خط الأساس الملاحظ، ولا يكشف فقد تيكات داخل الوسيط أو قبل وصولها إلى Named Pipe. Native Event IDs ليست بالضرورة عداداً متصلاً لجميع تيكات السوق، فلا نستخدم فرقها لحساب فقد السعر.
- بيانات المراقبة **في الذاكرة** وتُصفّر عند إعادة تشغيل Core أو تبديل هوية الحساب؛ لا ندّعي حفظ Timeline كامل بعد إعادة التشغيل.
- هذه بيانات **Accepted Pulse provenance**، وليست OOS لتجميد العقل Sniper، ولا PnL أو اختبار تنفيذ Broker.

## الفحوص
- `cargo test --locked -p braintrade-runtime sniper_tick_audit::tests` يشمل التبديل Native/Poll، الفجوات، Dense Tick clock، الفقد المدقق للـMailbox، بدء خط الأساس، تبديل حساب DEMO/REAL.
- `python3 -m unittest discover -s tests -v` يتضمن اختبار مصدر Native/Poll وأعداد Overflow والمفاتيح الخفيفة.
- `npm --prefix apps/terminal test` يتضمن رفض بيانات الحساب/الوضع/التوقيت المزورة وتوصيل زر تحديث تقرير Sniper.
- بوابات Linux وWindows Portable يجب أن تكون ناجحة على **آخر SHA** لهذه المرحلة؛ نجاح P1-K1 لا يُنقل تلقائياً.

## النقطة التالية
**P1-K3**: بناء `Frozen Sniper Tick Policy` فعلي بمكوّن مستقل عن دراسة M1: Snapshot ثابت من إعدادات Classic/Learner والسياسات والأوزان قبل التيكات التالية، تسلسل مصدر وزمن متّسق لكل حدث، احتساب توافق القرارات فقط مع ضمان عدم تسريب عينات تعلم المستقبل. كل مصدر انقطع/تبدل يصنّف Unknown للتقييم، ولا تُحتسب نتائج Paper كأرباح وسيط.
بعدها تبقى **G2 MT5 Demo فعلي، G3 Windows WebView2 نقر بصري، EA MetaEditor، G4 مخاطر Broker الحقيقية، G5 OOS مستقل وG6 إثبات الأداء بعد التكاليف** غير معتمدة قبل اختبار حقيقي.

**مهم:** هذه المرحلة لا تساوي 100% جاهزية Live ولا فحص أرباح. استكمال الفحوص الآلية لا يثبت جودة الاستراتيجية المالية.
