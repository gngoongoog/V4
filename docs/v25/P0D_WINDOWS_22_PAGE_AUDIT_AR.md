# Enterprise V25 — P0-D / Windows 22-page source & navigation audit

## الهدف والنطاق
هذه مرحلة تدقيق واجهة **React + Tauri + Rust Core** ذات الـ22 صفحة بعد P0-E. الهدف إثبات أن تعريف الصفحات ومسارات Core وأوامر Tauri موجودة ومترابطة، وتثبيت عزلة عرض البيانات عند تبديل الحساب أو الصفحة، وليس إعلان تشغيل WebView2 الحقيقي بنسبة 100%.

## المشكلة المعالجة
كانت `pageData` و`pageError` ووقت التحديث محفوظة بحالة React دون ربطها بنطاق الصفحة/هوية حساب MT5 المعروض. كان `PanelReadFence` يمنع استجابة IPC متأخرة من الكتابة بعد التبديل، لكن **بقايا بيانات قديمة من state سابق** قد تظهر لحظة بين تغيير الصفحة أو هوية الحساب وتنفيذ `useEffect` الذي يصفّرها. وقد تعرض صفحة جديدة بيانات/وقت تحديث الصفحة السابقة قبل جلب المصدر الصحيح.

**الإصلاح:** الاحتفاظ بالبيانات والخطأ ووقت التحديث على هيئة `{scope,value}`؛ لا يعرض React بيانات أو خطأ أو زمن تحديث إلا إذا طابق النطاق الحالي `[PageId, MT5 broker context, preview]`. يبقى Generation Fence مفعلاً أيضاً ضد الاستجابات المتأخرة. هذا دفاع عرض وليس تفويضاً بالتداول.

## واجهة التنقل
- القائمة ذات 22 صفحة كانت تختصر أول 11 صفحة عند طيها، وقد تخفي الصفحة الحالية إذا دخل المستخدم من رابط سريع إلى إحدى الصفحات الإضافية. الآن تبقى **الصفحة النشطة** ظاهرة حتى مع طي القائمة.
- أضيف `aria-current="page"` لزر الصفحة النشطة و`aria-expanded` لزر كل الصفحات.
- لا توجد أزرار جديدة تغير وضع MT5 أو تبعث طلب START. جميع التغييرات في العرض والتنقل وقيود الاختبار.

## تدقيق المصدر الآلي: 22 صفحة
`scripts/audit_v25_windows_pages.py` يقارن تلقائياً:
1. قائمة `PAGES` الدقيقة (22 ID فريد) مع `PageId` في TypeScript.
2. مسار GET لكل صفحة مع قائمة `allowed_read_route` المحصورة في Rust Tauri، باستثناء Dashboard الذي يعتمد Stream الحالة.
3. وجود إمكانية التنقل لجميع الصفحات وبقاء العنصر النشط ظاهراً عند الطي.
4. وجود Render Fence وGeneration Fence وغياب وصول المتصفح لمفتاح `ipc.key` أو HTTP Core مباشرةً.
5. وجود معالجات Tauri المسجّلة لأوامر `invoke` الصادرة عن واجهة React.
6. وجود مكونات الوظائف الرئيسية (المخاطر، التنفيذ، الإعدادات، القناص، backtest، backup، العقول) وData Explorer لبقية الصفحات.

تنتج بوابة بناء Windows الملف `test-output/v25/windows-page-matrix.json`. اختبارات `tests/test_p0d_windows_page_matrix.py` تحاكي حذف مسار/تكرار صفحة/حذف حماية عرض/حقن أمر Tauri غير مسجّل، ويجب أن تفشل مصفوفة التدقيق.

## الحدود المهمة
- **P0-D source matrix:** يمكن أن تصبح PASS من CI، لكنها **ليست** اختبار نقر في WebView2.
- **Windows WebView2 22-page click-path:** `NOT TESTED` إلى أن يفتح الجهاز الفعلي كل صفحة ويختبر التفاعل والتسلسل والرجوع ومعالجة الأخطاء.
- **22-page visual review at target resolutions:** `NOT TESTED` (اختبارات Slint السابقة لم تكن واجهة React/Tauri V25).
- **Demo MT5/Native EA:** `NOT TESTED` حتى MetaEditor وحساب Demo فعلي.
- **REAL execution / 100%:** لا موافقة؛ يجب المرور ببوابات قبول التشغيل المالي والوسيط قبل ادعاء جاهزية نهائية.

## اختبار Windows اليدوي اللاحق
عند توفر Windows x64 + WebView2 افتح `BrainTradeNext.exe` بدون MT5 أولاً. راجع جميع الصفحات الـ22؛ تحقق من أزرار الشريط والطي، حالة انتظار Core وحالة الخطأ عند فصل الاتصال. أعد تشغيله مع حساب MT5 Demo وتأكد أن كل شاشة تعرض الحساب الصحيح بعد تبديل الرمز أو Login. افتح Confirmation Dialog لـSTART لكن **لا تضغط تأكيد تداول REAL**. جرّب Refresh لكل صفحة، معاينة التصميم، صفحات النسخ، الرسوم، الخبر، الأداء، النظام. سجّل PASS/FAIL مع صورة لكل عنصر فاشل. لا تعتبر المصدر أو CI بديل تجربة WebView2 فعلية.
