# BRAINTRADE V25 — G6-A | دراسة مستقبلية مسجّلة مسبقاً (أسعار Demo ورقية فقط)

## ما الذي أُنجز فعلياً؟
بدأنا G6 بعد اختبارات نزاهة G5. بدل الادعاء بوجود تحسن ربحية من غير عينة مستقلة، أضفنا دراسة عملية بخطتين منفصلتين:
- **Register قبل جمع النتائج:** تحفظ معرّف نسخة منسق Expert المجمّدة الموجودة بالفعل، وتاريخ التسجيل، وبصمة SHA-256 لصورة الاستراتيجية المجمّدة ولسياق حساب MT5، وعدد آخر السجلات الموجودة لحظة التسجيل. تصنع ملف JSON حصرياً، ولا تسمح باستبداله بصمت.
- **Audit بعد بدء فترة الاختبار:** لا تقبل من السجل إلا قرارات Frozen/Adaptive وأزواج Paper المنشأة بعد مرور مهلة زمنية مسجلة مسبقاً (الحد الأدنى 30 دقيقة). تستعمل فحص G5-D الأصلي للقرار السابق للنتيجة، والعمولات والانزلاق والـTP/SL ومدة الاحتفاظ والتزامن.

## ما الذي يمنعه هذا التصميم؟
1. تسجيل خطة دراسة لنسخة منسق غير مجمّدة أو غير نشطة أو زمن إنشائها بعد التسجيل.
2. إعادة استعمال أرقام قديمة حصلت قبل التسجيل، وإن كانت مربحة.
3. تعديل ملف الدراسة بعد التسجيل دون تغير بصمة الملف، أو تبديل حساب/رمز/سياسة النسخة المجمّدة بعد التسجيل.
4. انتقاء عينات غير متطابقة في الزمن أو غير مكتملة التكلفة على أنها مقارنات مقبولة.
5. حذف جزء من الصفوف القديمة من قاعدة البيانات إذا قل عددها أو رجع أحدث Timestamp المخزن عن لحظة التسجيل.
6. إعادة تسمية بيانات عينات الأسعار بأنها نتائج تنفيذ Broker؛ التقرير يُظهر broker_pnl=null وindependent_oos=false وmodel_promotion_allowed=false دائماً.
7. التقرير يعرض حالات "أدلة غير كافية" إن لم يجمع 30 زوجاً مؤهلاً على الأقل في 5 أيام UTC مختلفة، وحتى عند كفايتها يبقى تقريراً **وصفياً ورقياً**.

## حدود جوهرية لا نريد إخفاءها
- ملف التسجيل محلي وله Hash لكنه **ليس طابعاً زمنياً خارجياً موثوقاً**. يستطيع صاحب الجهاز تغيير ساعة النظام أو إنشاء ملف بتاريخ متلاعب به. لتوثيق الزمن بصورة مستقلة، يحتاج تسجيل Hash لدى طرف خارجي ذي توقيت مثبت؛ السكربت لا يدعي أنه فعل ذلك.
- Adaptive يستمر بالتعلم خلال المراقبة، فلا توجد نسخة Adaptive مجمّدة ثابتة بحد قطع تدريب مستقل. وبالتالي لا يجوز الادعاء أن النتائج اختبار OOS مستقل لاستراتيجية ثابتة.
- Frozen وAdaptive هنا **نتائج Paper مبنية على أسعار BID/ASK الملتقطة**، وليس كل منهما صفقة MT5 منفذة؛ عينة الأسعار المتقطعة قد تفوّت وقفاً أو هدفاً بين العينات.
- نجاح 30 صفقة و5 أيام هو شرط أولي للتوصيف، وليس حجماً كافياً بذاته لإثبات قوة إحصائية، ولا يضمن الإيجابية بعد الانزلاق الفعلي ورفض الأوامر.
- اختبار المنظومة الفعلية يتطلب جمع بيانات جديدة من جهاز المستخدم على حساب MT5 Demo بعد فتح السوق؛ لا توجد اليوم عينات فعلية جديدة تم جمعها أو نتائج ربح مثبتة.

## طريقة التشغيل
يلزم وجود Core SQLite حقيقي يحتوي Frozen Expert run مُفعل قبل بدء الدراسة. السكربت لا يتصل بـ MT5، ويقرأ SQLite قراءة فقط.

أولاً، قبل فترة القياس، وبعد تجميد المنسق من واجهة Windows:

```bash
python scripts/audit_v25_g6a_preregistered_quotes.py register --db "PATH_TO_CORE.sqlite" --run-id "FROZEN_RUN_ID" --manifest "g6a-study-manifest.json" --embargo-minutes 30
```

احتفظ ببصمة manifest_sha256 التي يعرضها البرنامج في مكان موثوق بتوقيت خارجي إن أردت إثبات التسجيل مستقلاً. لا تعدل الملف الأصلي.

بعد جمع قرارات ونتائج Demo المستقبلية:

```bash
python scripts/audit_v25_g6a_preregistered_quotes.py audit --db "PATH_TO_CORE.sqlite" --manifest "g6a-study-manifest.json" --output "g6a-evidence.json"
```
