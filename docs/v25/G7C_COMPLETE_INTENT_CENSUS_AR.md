# BRAINTRADE V25 — G7-C | إحصاء كل أوامر MT5 ضمن دراسة Demo

## لماذا هذه المرحلة؟

G7-A يربط قرارات Frozen / Adaptive ببصمتها ووقت اتخاذها؛ G7-B يثبت سلسلة الربط المحلية من قرار Adaptive إلى أمر `system` ثم سجل وسيط MT5 Demo مغلق بالكامل. لكن **الاكتفاء بالصفقات المكتملة وحدها** قد يجعل الأداء يبدو ممتازاً حتى لو كانت هناك أوامر غير مرتبطة، مرفوضة أو معلقة.

هذه المرحلة تضيف `scripts/g7_full_intent_census.py`، برنامج تدقيق لقراءة قاعدة Core **فقط** دون إرسال أوامر أو تغيير بيانات/مخاطر.

## نطاق المقام الذي يتم إحصاؤه

- لكل سياق حساب/رمز مسجل في `g7_pair_registrations`، تراجع الأداة **كل** `broker_commands` من نوع `open` المسجلة بعد بداية أول مجموعة G7 في ذلك السياق، وحتى لحظة التدقيق.
- تتبع داخل هذه المجموعة أوامر العقول الأخرى وأوضاع التداول الأخرى وتفصلها عن مقام المقارنة المؤهل.
- المقام المؤهل من فئة `eligible_system_demo_open_intents`: أوامر `system` على نفس الحساب، بوضع Expert / Scalping / Swing يملك تسجيل G7 مسبقاً، وبهدف `demo`، بعد بداية مجموعة ذلك الوضع. لا يتم استبداله بعدد الرابحين.
- `exactly_linked_open_intents`: العدد المرتبط فعلياً بسجل G7-B المطابق تماماً. باقي الأوامر المؤهلة تُسجل `unmatched_eligible_demo_open_intent`.
- `locally_verified_full_demo_closes`: عدد المراكز المقبولة بسبب اكتمال إغلاقها والتحقق من العمولات وسجل القبول الأول. نتائج الأوامر المفتوحة أو المرفوضة أو غير القابلة للتدقيق لا تتحول إلى أرباح افتراضية.
- الأمر صاحب مصدر غير صالح أو هدف `live` ضمن النطاق يُذكر كخلل مستقل. وتكتشف الأداة عينة Broker بعد بداية الدراسة لا تحمل ارتباطاً مقبولاً بقرار G7.
- أي صفقة بدأت قبل تسجيل دراسة الوضع ثم أغلقت بعدها تُسجل `pre_registration_open_closed_in_cohort` كصفقة تاريخية متداخلة، ولا تُعتبر عينة G7 جديدة أو مخالفة. وتبقى عينات الأوضاع غير المسجلة خارج مقام G7.
- كل النتائج تستمد من `g7_core_source_audit` و `g7_demo_broker_lineage` قبل الحساب؛ أي تعديل في بصمات الأدلة يوقف التدقيق.

## تشغيل القراءة فقط

```powershell
python scripts/g7_full_intent_census.py --db "C:\path\to\core.sqlite" --output "g7-c-report.json"
```

المسار مثال وليس اسماً مؤكداً لملف Core. استخدم موقع قاعدة البيانات الفعلية. الأداة تفتح اتصال SQLite `mode=ro` وتبدأ معاملة قراءة للحصول على Snapshot ثابت، وترفض الكتابة فوق تقرير سابق.

## قراءة النتائج

| الحقل | تفسيره |
| --- | --- |
| `all_open_intents_in_registered_accounts` | كل أوامر الفتح في الحسابات والفترة المحددة، بما فيها أوامر خارج دراسة G7 |
| `eligible_system_demo_open_intents` | مقام أوامر الوضع المشمول والصادرة عبر `system` إلى Demo |
| `exactly_linked_open_intents` | أوامر مقام الدراسة المرتبطة بدليل القرار المسجل |
| `matched_unverified_or_unclosed` | أوامر مطابقة لكنها ليست أرباح Broker مثبتة |
| `full_close_fraction_of_eligible_open_intents` | **تغطية دليل الإغلاق** وليس نسبة نجاح الاستراتيجية |
| `local_command_census_complete` | نتيجة مراجعة كمال دفتر الأوامر المحلي، وليست موافقة لإطلاق Live |
| `anomalies` | أوامر مؤهلة لم يتم ربطها، بيانات تالفة، تداخل/إسناد مزدوج أو عينات وسيط غير موثقة |

يظل `status=inconclusive` مهما بدت إحصاءات التغطية جيدة، لأن **Frozen لم ينفذ صفقة مقابلة**، ولم يتم التحقق بشكل مستقل من صحة توقيت السوق أو جميع سجلات الوسيط أو تفوق Adaptive على OOS حقيقي.

## اختبارات المصدر

```powershell
python -m unittest discover -s tests -p "test_g7_full_intent_census.py" -v
```

يغطي الاختبار صفقة متحققة محلياً، أمراً زائداً لم يرتبط بالدراسة، مركزاً مفتوحاً، وضع تداول آخر، عقل آخر، هدف LIVE غير متوقع، أمر JSON تالفاً، قراراً ناقصاً، بيانات G7 معدلة وساعة غير صحيحة.

## حدود النسخة

- هذه إحصائية شاملة **لأوامر الفتح التي يعرفها Core** في سياق الحسابات المسجلة؛ لا يمكن إثبات أنها تشمل أوامر تنفيذت يدوياً في MT5، أو حسابات لم تُسجل في الدراسة.
- لا يمكن للأداة إثبات أن كل الفرص السوقية غير المتداولة تم تسجيلها، وهي تحصي القرارات الموجودة في جدول G7.
- لا يوجد ذراع Frozen منفذ لدى الوسيط، ولا اختبار ربحي مقارن، ولا موافقة LIVE.
- لا تغيير في `main` أو محرك أوامر التداول أو اللوت أو المخاطر.

**الخطوة بعد G7-C:** مراجعة تكامل نوافذ التجربة ومنع الإسناد الزائف عند وجود دراستين متداخلتين، ثم بناء تقرير قابل لإعادة التشغيل على بيانات Demo فعلية منفصلة عن بيانات التدريب، مع معايير نجاح مسبقة واعتبار الحالات غير الحاسمة `inconclusive`.
