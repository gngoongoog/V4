# BRAINTRADE V25 — G7-H | استلام تجربة MT5 Demo الفعلية (بدون تشغيل صفقات)

## لماذا هذه المرحلة؟

G7-A إلى G7-G لها أدوات تدقيق متخصصة نجحت في اختبارات اصطناعية وداخل Rust، لكنها **لا تعني** أن تجربة تداول حقيقية اكتملت. G7-H يجمع الأدلة في تقرير واحد **من قاعدة Core الفعلية** ويعلن الحالات الناقصة بالتسمية. لا ينشئ بوتاً آخر ولا يزيد عدد العقول، ولا ينفذ أي صفقة أو يغيّر إعدادات المخاطر.

الملف: `scripts/g7_demo_acceptance_packet.py`. يبدأ بقراءة G7-A، يرفض تعارض الدراسات G7-D، يتحقق من ربط MT5 Demo G7-B، يحصي **كل** أوامر الفتح G7-C، يفحص Candidate المختومة G7-F، ثم يقبل اختيارياً Manifest قبل الاختبار G7-E ونسخة قاعدة قبل إعادة التشغيل G7-G.

## على ويندوز — عندما يتوفر الجهاز

### (أ) التشغيل الأول

1. افتح تطبيق BRAINTRADE Windows والـMT5 Demo الحقيقي (لا تستخدم حساب REAL لهذا الاختبار).
2. من التطبيق تحقق أن الحساب Demo فعلاً، والرمز المطابق مسجل، وبيانات Tick صحيحة. استخدم START/STOP المعتادين، **لا** ترسل أوامر من برنامج التدقيق.
3. **قبل تسجيل أي شمعة بحثية**: أوقف الدخولات الجديدة بـSTOP، وتأكد من تسوية الأوامر والمراكز، ثم أنشئ `freeze` و`seal_candidate` عبر المسار الرسمي الموجود في Core. بعد اكتمال التجربة، لا تحاول إعادة كتابة دراسة قديمة.
4. حدد **مجلد بيانات Core الحقيقي** (قد تحدده قيمة `BRAINTRADE_DATA_DIR` عند استخدام نسخة مخصصة). قاعدة البيانات التي يفتحها محرك Core اسمها **`events.sqlite`**. لا تخمن المسار ولا تحذف قاعدة قديمة؛ راجع موقع بيانات التطبيق أو سجل تشغيل Core. لا ترفع ملف SQLite الذي يحتوي بيانات التداول إلى Pull Request عام.

أداة التقرير لا تتطلب أن يكون السوق مفتوحاً وقت تشغيلها، لكن **الأدلة الحقيقية نفسها تتطلب اختباراً سابقاً على Demo ببيانات وقتها**.

### (ب) استخراج تقرير واحد بدون تعديل القاعدة

من جذر المشروع وفي بيئة Python 3.11+:

```powershell
python scripts/g7_demo_acceptance_packet.py --db "C:\ACTUAL_DATA_DIR\events.sqlite" --output "g7-h-acceptance.json"
```

المسار `C:\ACTUAL_DATA_DIR` **مثال فقط**، استبدله بالموقع الحقيقي الذي يستخدمه Core.

يرفض البرنامج إعطاء نجاح وهمي عندما لا توجد دراسة مسجلة، أو لم تُنفذ صفقة، أو كانت الصفقة مفتوحة وغير محسومة، أو كانت بصمة أدلة Core غير متطابقة. يخرج **ملخصاً بدون أرقام الحساب أو الصفقة**، لكن احتفظ به بشكل خاص إلى أن تراجع بياناته.

### (ج) التقرير بعد تجربة قبل/بعد إعادة التشغيل

أنشئ نسخة متناسقة ببرنامج `g7g_restart_continuity.py snapshot` أثناء وجود حالة معروفة قبل إعادة التشغيل. أعد تشغيل Core بالطريقة المعتادة فقط بعد ضمان الأوامر والمراكز آمنة، ثم أنشئ نسخة ثانية أو استخدم قاعدة Core الحالية بعد التأكد من الانتهاء. للتقرير الموحّد:

```powershell
python scripts/g7_demo_acceptance_packet.py --db "C:\ACTUAL_DATA_DIR\events.sqlite" --before "g7-before.sqlite" --output "g7-h-after-restart.json"
```

سيطابق دليل البحث الأصلي مع **كل** السجلات الجديدة، وسيوقف التقرير إذا نقصت أدلة سابقة أو تغيرت سياستها المختومة أو ظهر Backfill لشمعات قديمة. إذا لم تضع `--before` يُسجل `pre_restart_sqlite_snapshot_not_supplied` صراحةً ولا يدّعي اختبار إعادة التشغيل.

### (د) إضافة Holdout مسجل مسبقاً

إذا أنشأت `g7-e-registration.json` قبل أول قرار من الدراسة حسب تعليمات G7-E:

```powershell
python scripts/g7_demo_acceptance_packet.py --db "C:\ACTUAL_DATA_DIR\events.sqlite" --manifest "g7-e-registration.json" --before "g7-before.sqlite" --output "g7-h-full.json"
```

يشترط التقرير أن يكون Candidate المختوم **نفس `run_id` ونفس الحساب والوضع**، وأن يسبق ختمه بدء الاختبار. بيانات Adaptive الفعلية يمكن أن تتغير أثناء التجربة؛ وجود نسخة Candidate ثابتة **لا** يثبت أن Adaptive نفسه ثابت.

## تفسير التقرير: لا تخلط المقامات

| الحقل | معناه الفعلي |
| --- | --- |
| `paired_source_decisions` | قرارات Frozen/Adaptive في Core؛ ليست صفقات منفذة |
| `sealed_candidate_forward_receipts` | إشارات Candidate المحفوظة، وليست عقود MT5 |
| `eligible_demo_open_intents` | كل أوامر فتح `system` المؤهلة ضمن النطاق، بما فيها المفتوح وغير المرتبط |
| `locally_verified_closed_adaptive_positions` | الصفقات الفعلية المغلقة بالكامل والمربوطة محلياً بسجل Broker وعمولاته |
| `demo_open_intents_with_full_close_fraction` | تغطية أدلة الإغلاق، وليست نسبة الربح |
| `closed_subset_win_rate_descriptive` | نسبة وصفية للصفقات المقبولة المغلقة ضمن Holdout فقط؛ لا تُعمم على المفتوحة |
| `blockers` | الأسباب المحددة لعدم كفاية الأدلة أو عدم توفر اختبار ميداني مستقل |

لا تظهر النتائج الخام للحساب أو `position_id` داخل التقرير الموحد. ملف قاعدة البيانات الأصلي والنسخ المرفوعة يدوياً قد تحتوي بيانات حساب وأوامر خاصة ويجب حفظها محلياً.

## معيار إغلاق مشروع G7 برمجياً

1. نجاح فحوص G7 وResearch وLinux وWindows **لنفس Commit** في GitHub.
2. تقرير SQLite بلا تعارض مصدر أو فقدان أدلة بعد إعادة التشغيل.
3. أول تشغيل Demo على Windows: التحقق من الاتصال، قراءة الأسعار، بقاء STOP عندما لا ترغب بالدخول، أوامر MT5 الفعلية إن كانت هناك تجربة، وإغلاقها واحتساب الرسوم الحقيقية.
4. وجود Manifest Holdout مُنشأ **قبل** الاختبار، مع مسارات البيانات الناقصة وعدم اليقين. لا يوجد ختم وقت خارجي في المرحلة الحالية.
5. مراجعة بيانات Broker الأصلية عند المستخدم؛ أدواتنا لا تشكل إثباتاً مستقلاً للوسيط.

**قرار النشر:** حتى لو نجحت جميع النقاط المحلية، تظل حقول `release_authorized=false` و`independent_oos=false`. Frozen وCandidate مجرد إشارات بحثية، وليستا ذراعين منفذتين. لا تثبت هذه المرحلة عائد تداول أو تحسن مالي فعلي بسبب التعلم، ولا تغير تشغيل REAL أو القيود أو اللوت أو `main`.

عند توفر جهاز ويندوز، احفظ **التقرير JSON فقط** وقائمة الأخطاء أو لقطات شاشة صفحة التنفيذ لعرضها في المحادثة، ولا تشارك مفاتيح IPC أو بيانات حساب MT5 أو ملفات الأسرار.
