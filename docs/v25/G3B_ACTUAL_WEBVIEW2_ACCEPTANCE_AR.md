# V25 — G3-B: اختبار نافذة Windows الفعلية

نقطة البداية المؤكدة: G3-A عند `54ee875c88be1be2b1f4d251e292841079b9b4cd`.
Research `40157523353` وWindows `40157523342` وPortable `40157520471` نجحت جميعاً.
لا نعود إلى إصلاحات G2-M المكتملة آلياً؛ قبول MT5 الحقيقي يظل منفصلاً ومفتوحاً.

## التغيير

إضافة حزمة اختبار مستقلة `apps/windows-gui-tests` وبوابة CI تشغّل **BrainTradeNext.exe المبني فعلياً في G3-A** وتتحكم بـWebView2 عبر CDP على loopback. يبقى executable هو G3-A ومصدره وبصمته موثقان؛ التعديل الحالي لا يغير منطق المنتج أو يعيد تسمية EXE قديم كأنه بناء جديد.

يستخدم Playwright اتصال WebView2 الرسمي، مع مجلد بيانات وملف WebView مؤقتين وGateway معطل وأخبار offline. يفشل إذا وجد Core سابقاً على المنفذ. لا يفتح MT5 ولا يقرأ بيانات المستخدم ولا يضغط START ولا يرسل صفقة. رصد IPC يمرر الطلب الأصلي إلى Tauri دون بيانات بديلة.

## نطاق الاختبار الفعلي

- بدء نافذة Tauri والتحقق من STOPPED.
- فتح الصفحات الـ22، إثبات قراءة Tauri/Core المسموح بها لكل صفحة، جرد عناصر التحكم والتقاط العرض.
- الثيمات Dark/Smoke/Light؛ نافذة STOP وإلغاء Escape وعودة التركيز ثم تنفيذ STOP.
- عزل Design Preview؛ START يبقى معطلاً بدون MT5.
- تغيير الأوضاع الأربعة وحفظ العمولة صفر/7، ثم Learner/Confirmed وقراءة النتيجة من Core، وإلغاء التعديل المحلي.
- رفض مسار قراءة غير مسموح، والخروج الآمن من زر الواجهة، ثم إعادة تشغيلها والتحقق من حفظ الإعدادات والثيم.

التقرير JSON يسجل PASS/FAIL لكل خطوة ولقطات فعلية. جرد الأزرار لا يساوي اختبار كل زر؛ كل عنصر غير مُجرّب يبقى موسوماً `action_tested=false`. هذه المرحلة لا تثبت حسابات متصلة أو صفقة أو جميع الحالات البصرية أو جميع الشاشات والأبعاد.

**الحالة قبل CI:** NOT TESTED على Windows حتى يكتمل التشغيل وتُراجع الأدلة. لا يجوز وصف كتابة الاختبار بأنها نجاح له. تقرير `report.json` ونتيجة الوظيفة لنفس harness commit هما المرجع.

المصدر التقني: https://playwright.dev/docs/webview2
