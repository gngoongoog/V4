# BRAINTRADE V25 — G2-L | عدم اختلاق إغلاق لدى الوسيط

## السبب
كان Gateway يعيد state=closed عند اختفاء تذكرة مركز الإغلاق من قائمة المراكز المفتوحة أو كانت تخص Magic مختلف. لم يكن هناك order_send ولا إيصال خروج Deal، لكن Core كان يَقبل CLOSED كحالة نهائية للأمر.

## التصحيح
- عند عدم وجود نفس المركز المملوك للعقل، تتوقف محاولة الإغلاق بدون إرسال أمر MT5 وتُرجع state=cancelled مع سبب صريح: no close order sent.
- يمنع Core استقبال state=closed من Gateway كدليل إغلاق، بالإضافة إلى منع state=observed المفروض خارج مسار المصالحة.
- خروج الصفقة الحقيقي يعتمد على تاريخ DEAL موثّق والتطابق بين position_id والـticket وأحجام التداول، وليس مجرد اختفاء المركز.
- أوامر إغلاق المراكز المملوكة الموجودة فعلاً تبقى ترسل الحجم الحقيقي للوسيط وتخضع لنفس ضوابط التنفيذ.

## التحقق
أضيف اختبار Python للتذكرة غير المملوكة والتذكرة الغائبة مع عدم إنشاء أي order_send، ثم إغلاق تذكرة مملوكة بالحجم الفعلي.
أضيف اختبار Rust يرفض الحالة closed المزيفة ويحافظ على الأمر بدون تغيير حتى وصول cancelled صحيح ويؤكد عدم إنشاء أي إيصال Broker.

هذا الإصلاح لا يثبت أن منصة MT5 Demo استقبلت أمرًا فعليًا. بوابات GitHub Research وWindows وPortable واختبار الوسيط الحقيقي لا تزال معايير قبول G2.
