# BRAINTRADE V4 Enterprise V25 — P0-D2: تأكيدات المشغل وقبول صفحات Windows

## ما تم تغييره فعلياً في المصدر

- أصبح `START` يفتح موافقة مؤقتة مرتبطة بـ `contextKey`: Login وServer وSymbol وCurrency وDemo/REAL وaccount_trade_mode وحالة اتصال Core/MT5. تغير الحساب أو انقطاع الـGateway يلغي صلاحية الموافقة. زر بدء التداول غير متاح بدون Broker حديث أو أثناء تشغيل START سابق.
- حساب `REAL` يتطلب التأكد من نوع حساب MT5 الفعلي `account_trade_mode=2` ومطابقة رقم Login المدخل حرفياً؛ Demo يتطلب `account_trade_mode=0` وLogin فعلي صالح، من دون حقل تأكيد REAL. اختبار UI لا يحل محل التفويض النهائي من Rust Core وGateway.
- `STOP` والخروج الكامل يستندان إلى تأكيد من نفس جلسة الحساب. STOP يبقى متاحاً للطلب من واجهة Windows حتى عندما لا توجد أسعار موثوقة؛ Rust Core مسؤول عن الإيقاف. الخروج الكامل يبقى خاضعاً لقفل Core عند مراكز أو أوامر غير محسومة.
- نوافذ التأكيد تستخدم `role=dialog` و`aria-modal=true`، ويمكن الإلغاء بـ Escape والتنقل بين عناصر النافذة بـ Tab/Shift+Tab، مع إعادة التركيز إلى عنصر التحكم السابق.
- حالة Config وRisk وإعدادات الحفظ أصبحت مرتبطة بجلسة MT5؛ لا يعرض React قيماً من الحساب السابق بعد التحويل. `RiskEditor` يعاد إنشاؤه عند تبدّل سياق الحساب كي لا يحمل تعديلات نموذج المخاطر إلى حساب آخر.
- مسودة Bot Token وقرار حذف رمز Telegram أصبحت مقيّدة بحدود الجلسة، ولا تدخل أي طلب حفظ لحساب آخر. الانتقال إلى Design Preview يلغي تأكيدات START والمسودات الحساسة.

## الاختبارات الآلية

`apps/terminal/tests/operator-approval.cjs` يشغّل فعلياً منطق TypeScript لقرار بدء التداول تحت حالات Demo وREAL وتبديل Login وBroker stale ووقف تشغيل المحرك وغياب الحقول ورفض تأكيد Action مختلف. ويراقب وجود مسارات UI الحقيقية لطلبات التأكيد، وتقييد مسودات إعدادات الحساب والحماية من الاستجابة القديمة.

تشمل `npm --prefix apps/terminal test` الفحص الجديد، و`npm --prefix apps/terminal run build` يتحقق من TypeScript. وبوابة Windows Portable تشغّل الاثنين، مع اختبارات Rust وPython وCore. **لا تفتح CI شاشة WebView2 أو تتصل بـMT5 أو تنفذ طلب Broker**.

## G3 — قائمة فحص Windows اليدوية لكل صفحة

### حالات مشتركة يجب إجراؤها

1. بدون MT5 وبوجود/عدم وجود Core: يجب إظهار `OFFLINE/NOT AVAILABLE` لا أرقام تصميم على أنها حقيقية.
2. افتح START Confirmation على Demo، اقطع حالة اتصال Core أو بدّل Broker Login من داخل MT5: يفشل تأكيد Start القديم ويحتاج موافقة جديدة. لا تتجاوز تحقق Core.
3. اختبر Real Confirmation **بدون الضغط على تأكيد إرسال حقيقي**؛ قيمة مختلفة عن Login الصحيح تبقي زر التأكيد معطلاً.
4. تنقل من Settings إلى Risk ثم غير الحساب: لا تظهر مسودة Token أو Risk القديمة في الصفحة الجديدة. Design Preview لا يعيد الموافقات أو الأسرار بعد الإغلاق.
5. اختبر `Escape` و`Tab` و`Shift+Tab` في كل نافذة تأكيد، وعودة التركيز بعد الإلغاء.
6. أثناء عمل Backtest أو وجود أوامر عالقة، اطلب خروجاً كاملاً: Rust Core يجب أن يرفض حسب شروط السلامة، ولا ينبغي إغلاق العملية آلياً إذا رفض.
7. جرّب كل الصفحات على مقاسات 1366×768 و1920×1080، وتمرير الجداول وتقسيم الشاشة والوضع الليلي/الدخاني/الفاتح. سجل قص النصوص أو أزرار خارج الشاشة.
8. تحقق من `VERIFY_SYSTEM.cmd` و`Run-Demo-Acceptance.cmd`، دون افتراض أن تحقق الحزمة يثبت Fill أو MetaEditor Compile.

## حدود الاعتماد الحالية

- **Unit/source guards:** قابلة للتمرير عبر CI.
- **Windows Portable SHA/Build:** منفصل عن تحقق تفاعل WebView2.
- **G3 جميع الصفحات الـ22 من خلال UI:** `NOT TESTED` حتى تُجمع أدلة نقر وصور على Windows فعلي.
- **G2 MT5 Demo / EA Compile / Real trading profitability:** `NOT TESTED` خارج النطاق.
- **READY FOR REAL:** `false` حتى اجتياز بوابات القبول المالي والتقني المستقلة.

المرحلة القادمة من P0-D هي عزل وإلغاء ردود الكتابة المتأخرة بعد تبديل الحساب، ثم اختبار UI عبر WebView2 على الجهاز عندما يتوفر.
