## العيب المثبت والإصلاح

- GitHub لم يتضمن واجهة React/Tauri الحالية مباشرة، وكان بناء Windows يفك أرشيف V18، ثم Delta V23، ثم يطبق ترقيعات V24 وP0-A إلى P0-N. لذلك لا يكفي سحب المستودع لبناء النسخة نفسها.
- أُعيد تنفيذ خطوات بناء P0-N في مساحة مستقلة، وقورنت بأرشيف المصدر. فروق منطق الإنتاج اقتصرت على التعليقات وعلامة هوية EXE؛ توجد فروق أسماء وتفاصيل اختبارات. المصدر الأساسي المعتمد هنا هو ما بناه CI فعلياً.
- أُدخلت ملفات المصدر الناقصة وملفات Cargo/npm المقفلة من حزمة P0-N. أُضيف `apps/tauri` إلى workspace. لم يُغيّر منطق التداول أو التعلم في هذه المرحلة.
- مسار V25 الجديد يبني الملفات الملتزم بها مباشرة، باستخدام `npm ci` و`cargo --locked`، دون تركيب أرشيفات أو ترقيع المصدر عند البناء أو تثبيت Tauri CLI عالمي.
- أُعيدت أداة التحقق واختباراها من أرشيف المصدر إلى Git والحزمة. أُصلح اقتباس مسار Python في `VERIFY_SYSTEM.cmd` لدعم المجلدات ذات الفراغات.
- أُضيف فحص Core من working directory مختلف وبعد نقل مجلد الحزمة، وفحص اختصار Windows فعلي، ومنع فحص العزل من لمس Core يعمل مسبقاً على المنفذ.
- إصدار غلاف Tauri هو `0.25.0`؛ إصدار بروتوكول Core التاريخي يبقى `0.7.4`. لا تُخلط هوية الإصدار مع ترقية بروتوكول البيانات.
