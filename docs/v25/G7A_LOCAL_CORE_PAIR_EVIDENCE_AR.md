# G7-A — ربط مقارنة منسق Frozen / Adaptive بمصدر Core الحقيقي

**تاريخ التعديل:** 2026-10-26  
**النطاق:** Expert / Scalping / Swing على MT5 Demo، وبمسار Frozen Coordinator الموجود مسبقاً.  
**الموقع:** `crates/runtime/src/g7_capture.rs`، `frozen_coordinator.rs`، `scripts/g7_core_source_audit.py`.

## المنفذ فعلياً في الكود

1. عند تنفيذ **Freeze** للمقارنة البحثية، يكتب Core سجل `g7_pair_registrations` متضمناً معرف الدراسة، سياق حساب/رمز MT5، الوضع، تاريخ البداية المستقبلي وبصمة SHA-256 لسياسة Frozen الكاملة. الكتابة تتم في نفس معاملة SQLite التي تنشئ `frozen_coordinator_runs`.
2. عند اكتمال شمعة M1 مستقبلية تستوفي شروط `frozen_coordinator::observe` الأصلية، يحسب Core قرار **Frozen** بوزنه وإعداداته المحفوظة ويقابله قرار **Adaptive** الحالي. يحفظ الاثنين والسياق ونوع التغطية وبصمتي الإشارتين في `g7_paired_decision_evidence` بنفس المعاملة التي تحفظ `frozen_coordinator_decisions`.
3. لا تُستنسخ سجلات قديمة بأثر رجعي: التشغيل المجمد قبل G7 يظل قابلاً للفحص وفق المنظومة القديمة، لكنه لا يحصل على تصريح G7 جديد. إذا تغير Snapshot المسجل أو اتغير الحساب/الوضع أو أصبح التوقيت غير سببي، يفشل تسجيل دليل G7، ويرجع مسار البحث فقط دون إلغاء تنفيذ الصفقات أو إدارة الصفقات المفتوحة.
4. لا يوجد أي زر أو كود في G7 يرسل أوامر MT5، أو يعدل وزناً متعلماً أو مخاطرة أو لوت، أو يرقّي سياسة.

## أداة التدقيق الفعلية

بعد تجميع Core وتشغيل مقارنة جديدة على **حساب MT5 Demo**، يمكن تدقيق مصدرها محلياً:

```powershell
python scripts/g7_core_source_audit.py "C:\path\to\actual\core.sqlite" --output g7-local-evidence-report.json
```

**استبدل المسار بموقع قاعدة بيانات Core الحقيقي على الجهاز.** لا نفترض اسم ملف القاعدة أو موقعه مسبقاً. الأداة تفتحها `mode=ro` وتتحقق من كل تسجيل مقابل جدول Frozen وقرار Frozen/Adaptive المقابل وبصمة بيانات المصدر وتوقيت الدراسة. ترجع `not_started` إذا لم يبدأ جمع أدلة جديدة، و`inconclusive` إذا وُجدت مقارنة محلية صحيحة؛ لا ترجع `pass` أو إذن REAL.

## الحدود الصريحة

- هذا يثبت **سلامة الربط المحلي القابل لإعادة المراجعة**؛ لا يثبت أن الجهاز أو SQLite لم يُعدّلا خارج البرنامج أو أن التوقيت موقّع من جهة مستقلة.
- قرار Adaptive ليس سياسة مجمدة ثابتة: قد يتغير التعلم بين العينات. يُسجّل قرار Adaptive كما شوهد لحظتها، وليس ادعاءً بأن نسخة Adaptive كانت ثابتة طوال الدراسة.
- كل المقارنات **إشارات فقط**؛ ليس لدينا مجموعتان من أوامر الوسيط المنفذة ولا عوائد مالية متحققة لكلا الذراعين. نتيجة الورق أو الأسعار النظرية لا تُحَوَّل إلى P&L Broker.
- Sniper يعمل على Tick وليس مسار M1 المكتمل؛ **غير مشمول** بهذه الإضافة. يحتاج بروتوكولاً Tick مستقلاً.
- أداة `g7_prospective_audit.py` السابقة تطلب تعيين ذراع منفذ ونتائج وسيط Demo؛ لا تغذّيها هذه المقارنات الورقية وكأنها صفقات فعلية.
- إثبات أفضلية تعلم Adaptive، صلاحية التطبيق على حساب حقيقي، الاختبار على ويندوز والاتصال الفعلي بالوسيط **ما زال غير مُثبت**.

## الخطوة الهندسية التالية

بناء ربط اختياري منفصل بين معرف القرار الصادر وبين صفقة MT5 Demo المرسلة فعلاً، اعتماداً على دفتر أوامر Core ومعرف `position_id` ونتيجة الإغلاق والعمولات المقتطعة، على أن يسجل الذراع المنفذ فقط، ويبقي الذراع الآخر `counterfactual_signal`. عندها يمكن تشغيل تقييم مجدول مسبقاً مع حد عينات وCI إحصائي، وليس مجرد علامة نجاح اختبار برمجي.
