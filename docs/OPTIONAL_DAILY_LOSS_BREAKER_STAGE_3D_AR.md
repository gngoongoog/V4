# المرحلة 3D — قاطع خسارة يومية مستقل مع زرين Demo و REAL

## ما الذي يفعله؟
الصفحة Risk تشتمل على مفتاحين منفصلين:
- **Demo OFF افتراضياً:** يسمح بتكرار التجارب والتنفيذ التجريبي حتى لو تجاوزت خسارة اليوم حد القاطع، ولكنه لا يزيل اشتراط الستوب والهامش والعمولة وحجم العقد.
- **REAL ON افتراضياً:** يقفل الدخول الجديد إذا بلغ الحساب حد الخسارة اليومي. يمكنك إيقافه يدوياً وأنت في STOPPED، لكنه خيار مرتفع الخطورة خصوصاً مع حساب صغير ومخاطرة مؤقتة مرتفعة.
- حد الخسارة `daily_loss_percent` افتراضياً 2% (من 0.1 إلى 10) يؤثر فقط عندما يكون القاطع المعني مفعلاً.
- لا يتأثر تدريب العقول الافتراضي SHADOW/PAPER ببوابة إرسال أمر MT5. تعطيل القاطع لا يضمن تعلماً أفضل؛ يلزم تقييم خارج العينة واستقرار نتائج التدريب.

## المحاسبة
يقرأ Core بيانات الحساب التي يجلبها MT5 لجميع الرموز مع `today_net` (جميع صفقات اليوم بعد العمولة والسواب والرسوم)، `balance` و`equity`. يقدّر الرصيد قبل صفقات اليوم = `balance - today_net` والخسارة الإجمالية = `baseline - equity`، فتدخل في الحساب جميع المراكز المفتوحة بما فيها المراكز الخارجية، دون حصر بـ XAUUSD. يحسب اليوم بتوقيت بغداد UTC+3. عند غياب سجل التداول أو تناقضه يُرفض الدخول الجديد إذا كان القاطع مفعلاً.

بوابة MT5 تعيد حسابه بصورة مستقلة من سجل صفقات اليوم والرصيد الحالي وEquity الفعلي، قبل الفحص ثم بعد تسجيل إرسال الأمر بالدفتر. قاطع اليوم فقط قابل للتبديل؛ فحوص MT5 للعقد والوقف والتكلفة واللوت والهامش ومنع إعادة الإرسال قائمة دائماً.

## ديمومة القفل
عند بلوغ الحد تُسجّل قاعدة بيانات Core وقاعدة بيانات بوابة MT5 صفاً دائماً يتضمن (السيرفر، رقم الحساب، العملة، يوم بغداد)، وليس رمز التداول. إيقاف القاطع مؤقتاً يسمح بالدخول الجديد ولكنه **لا يمسح صفّ القفل**؛ وعند إعادة التشغيل في نفس اليوم يتجدد المنع. في اليوم التالي يعود القاطع إلى المراقبة. تغيير نسبة الخسارة أو إعادة تشغيل البرنامج لا يمسح قفل اليوم السابق.

## قيود محاسبية مهمة
تقدير البداية باستعمال Balance ونتائج عمليات التداول لا يعادل كشف حساب محاسبي لحظة منتصف الليل إذا كان هناك مراكز مرحّلة من اليوم السابق أو تغيرات تمويل معقدة. هذه سياسة محافظة تعتمد على Equity، وليست محرك تدقيق محاسبي متكامل لكل أحداث الإيداع والسحب. الفجوات والتنفيذ المتأخر قد تتجاوز حد القاطع؛ القاطع يمنع *الدخول الجديد* ولا يغلق مراكز قائمة بشكل قسري ولا يضمن مقدار خسارة أقصى.

## الاختبارات المطلوبة
- Rust: توافق JSON القديم، Default OFF Demo / ON REAL، يوم بغداد، استمرار القفل عبر تبديل الرمز وعودة تشغيل Core، ضعف البيانات fail-closed.
- Python: قبول Demo OFF حتى لو التاريخ غير متاح، رفض Demo ON عند غياب التاريخ، قفل REAL عند الخسارة، تجاوز OFF المسموح به وإعادة ON لنفس اليوم، إعادة تشغيل Gateway، رفض عند انخفاض Equity خلال تجهيز الإرسال.
- CI: Research + Linux + Windows على آخر SHA والاختبار النهائي اليدوي على Windows/MT5 Demo.
- LIVE الحقيقي لا يعتمد على CI وحده؛ يلزم مطابقة نتائج MT5 المحاسبية في الوسيط الفعلي.
