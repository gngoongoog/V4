# بروتوكول الاعتماد المؤسسي V4 — شروط ما قبل حساب REAL
**تاريخ التوثيق:** 2026-10-22

## الوضع الرسمي
تجارب Rust وPython وWindows GitHub Actions تثبت إمكانية تجميع المشروع وسلامة بعض عقود البرمجيات، ولا يمكنها إثبات كفاءة استراتيجية تداول مالي على سوق حقيقي. النجاح في التجارب الاصطناعية/المحاكاة **ليس اعتماداً للعمل الإنتاجي ولا ضماناً للربح**. لا يجوز عرض المشروع على أنه «جاهز 100%» دون تقرير اختبار حساب وسيط Demo حقيقي وتوقيع قبول التشغيل. نتائج نماذج Challenger البحثية ليست نتائج العقول التنفيذية؛ الصفقة الورقية لا تُحوّل إلى ربح MT5.

الحالات أدناه **لم تُسجل كاختبارات مكتملة** لمجرد وجود كود أو نجاح CI. المسؤول عن الاختبار يضع نتيجة، وصور/سجلات MT5 وأرقام أوامر وسيط قابلة للمطابقة، وcommit نهائي، وتاريخ بيئة الاختبار.

## بوابات الاعتماد، بالترتيب

### 1. ثبات النسخة والحزمة
- [ ] تثبيت SHA فريد في main وإصدار حزمة Windows Desktop / Core / Gateway من **نفس SHA**.
- [ ] كل اختبارات Research / Linux / Windows ناجحة على SHA نفسه، مع فحص رسم جميع صفحات Slint.
- [ ] تشغيل حزمة نظيفة Windows بعد إغلاق كل نسخ MT5 والمشروع ثم فتحهما بالتتابع؛ تأكيد عدم تضارب عمليات وقواعد بيانات قديمة.
- [ ] اختبارات استرجاع نسخ احتياطية SQLite تشمل WAL وجداول الصفقات والتعلّم والقفل والحساب، والتحقق من سلامة المفتاح الأجنبي.
- [ ] تسجيل الخطأ في الداشبورد والسجل بشكل يمكن تشخيصه، من غير تسريب كلمات المرور أو رموز Telegram.

### 2. ربط MT5 وموثوقية التنفيذ
- [ ] تأكيد الرقم الفعلي Login/Server/Currency/TradeMode/Leverage ووقف كل فتح جديد إذا تغيرت هوية الحساب أو صار Snapshot قديماً؛ إعداد الرافعة 1:500 كتجربة **لا يغيّر الرافعة الفعلية لدى الوسيط**.
- [ ] اختبار سوق مفتوح Demo: شراء/بيع بأصغر حجم مسموح 0.01، تسوية `order_send` ونتائج requote/reject/partial/unknown واللوت الأدنى وخطوة اللوت.
- [ ] اختبار تحولات اتصال الشبكة وRestart بعد أمر مجهول: **لا يعيد فتح نفس الأمر** أو ينسب أمر وسيط مفقوداً على أنه فاشل من دون مصالحة History.
- [ ] اختبار وضع hedging وnetting (إذا دعمهما الوسيط)؛ منع التداخل بين ملكيات العقول والمراكز الأخرى؛ عدم غلق صفقة بشرية بالغلط.
- [ ] اختبار CLOSE وSTOP وإلغاء دخول حتى عند تخطي قاطع الخسارة، مع تأكيد إغلاق الصفقات الفعلي من History والـPositions.
- [ ] مطابقة دفتر التنفيذ المحلي مقابل كشف `MT5 history_deals_get` وعمولات الجولات المفتوحة/المغلقة، والتبييت، والرسوم، والانزلاق، والـpartial fills.

### 3. المحاسبة والرافعة والحساب الصغير
- [ ] التحقق على **عقد 1 لوت** من عمولة **7$ round-trip**، وعلى 0.1 من **0.70$**، وعلى 0.01 من **0.07$**، و**0$** عند الحساب صفر عمولة. الاختبار يجب أن يقارن مع طريقة وساطة العمولة الفعلية، فقد يحمّل الوسيط نصفها عند الدخول والنصف الآخر عند الإغلاق.
- [ ] التأكد من أن لمس TP لا يعني ربحاً إذا كان الربح الإجمالي أقل من مجموع العمولة والسبريد والانزلاق.
- [ ] تجربة رأس مال 100$ على Demo برصيد حقيقي للحساب التجريبي، مع رافعة وسيط مؤكدة، ومتطلبات Margin/StopLevel/FreezeLevel للذهب. إذا وقف 0.01 لوت يتجاوز ميزانية المخاطرة الفعلية فلا يجوز اختراع لوت أصغر من الحد الأدنى.
- [ ] التحقق من فروقات حساب الحركة في XAUUSD حسب `contract_size`, `tick_size`, `tick_value_profit/loss`، وDigits وعملة الحساب، بدلاً من افتراض 1 نقطة = قيمة ثابتة.
- [ ] تسجيل تغيرات Equity وBalance والهامش الحر والعمليات غير التداولية وودائع/سحوبات ومراكز محمولة من اليوم السابق: حدود «بداية اليوم المقدّرة» ليست دفتر حسابات يومي دقيقاً دائماً.

### 4. المخاطرة وقاطع الخسارة
- [ ] Demo OFF: يمنع تعطيل قاطع اليوم **فقط** ولا يُلغي حواجز المارجن واللوت ووقف الخسارة وفحص الأسعار.
- [ ] Demo ON وREAL ON: اختبار بلوغ حد الخسارة، اللاتش الدائم عبر Restart والرموز المختلفة والحسابات، وعدم فك القفل بالتبديل بين ON/OFF حتى يتغير يوم بغداد.
- [ ] عدم فتح أي صفقة جديدة إذا تاريخ الوسيط اليومي غير موثوق وكان القاطع مفعّلاً (fail closed).
- [ ] اختبار قفزات السعر ووقف الخسارة: حدود المخاطرة تقديرية وقد تتجاوزها الخسارة فعلياً، حتى مع الرافعة العالية.
- [ ] لا يُسمح بمخاطرة REAL مرتفعة بحجة أن حجم الحساب 100$ أو أن الرافعة 1:500؛ يجب تقييم خسارة وقف 0.01 الفعلية مقابل رأس المال.

### 5. العقول وتقييم جودة التعلّم
- [ ] اختبار كل وضع (Expert, Scalping, Swing, Sniper) بتفعيل وإطفاء أزراره، وعدم تسرّب قرار وضع إلى الآخر.
- [ ] تدقيق أن المنسق **SYSTEM فقط** يفتح أوامر MT5 في الوضع المحدد، وأن العقول الفرعية لا تتجاوز صلاحيات Shadow/Paper، وأن الأمر المنسوب لعقل آخر موثق بوضوح.
- [ ] مقارنة سجل نتائج Demo الحقيقي بعد العمولات مع الإشارات والدفتر: لا يُحسب التدريب الورقي كأنه صفقة Broker مغلقة.
- [ ] اختبار `frozen Challenger` البحثي بمراجعة تسلسل بيانات التدريب والتوقع والنتيجة المستقبلية، دون خلطه بأوزان عقول MT5.
- [ ] تشغيل تجارب Frozen Shadow على أسعار جديدة بعد تاريخ التجميد فقط؛ الفصل عن REAL وعدم تحديث النسخة المجمدة، ومنع إدخال صفقة ثانية قبل انتهاء الأولى.
- [ ] التحقق من دراستي المقارنة: أفق 5 دقائق الموحد، و**مسار SL/TP/مدة احتفاظ مستقل** لكل طرف؛ تظهر العينات غير المكتملة وفجوات أكثر من 15 ثانية.
- [ ] مقارنة نتائج فترة مستقبلية مجمّدة ومحددة مسبقاً **لا تدخل تدريب العقل المختبر** مع فترات متعددة للسوق (ترند، تذبذب، أخبار، سبريد مرتفع).
- [ ] اختبار محرك Twin مستقل **للمنسق الرئيسي بكامل أوزانه وسياسة الأوامر والخروج**؛ هذا لا يتحقق حالياً بمجرد تجميد مستشار فرعي، ويجب اعتباره بنداً مفتوحاً.
- [ ] إقرار سياسة قبول مسبقة بعدد كافٍ من الصفقات المستقلة والنتائج المستقرة بعد الرسوم مع حدود فقد المقبول وقياس التراجع، وعدم تغيير العتبات بعد رؤية النتائج.

### 6. الجودة التشغيلية ومراقبة الأداء
- [ ] قياس زمن السوق `tick_time`، وقت القرار، بدء الإرسال، نتيجة الوسيط والـP95/P99 أثناء الضغط؛ **Latency الناجح في المعمل ليس إثباتاً لزمن تنفيذ حقيقي**.
- [ ] تجربة انقطاع الشبكة، خمول MT5، وإعادة الاتصال، وتعطل الأخبار والتلكرام والتخزين وإغلاق Windows؛ لا تُفتح أوامر نتيجة وصول بيانات قديمة.
- [ ] اختبار واجهة الحاسوب يدوياً، خصوصاً كل زر، اختيار العقول، حفظها بعد إعادة التشغيل، أذونات الخدمة، النص العربي، RTL، وتوافق القياسات.
- [ ] تنبيهات التلكرام باللغة العربية (الأمر، الرفض، القاطع، حالة الحساب) تميّز الإرسال المحاول عن الصفقة المنفذة والمؤكدة.
- [ ] التحقق من الجهة التي يثق بها المستخدم للوصول Remote/VPN؛ عدم كشف Core أو Gateway على الإنترنت.

### 7. الإفراج عن حساب REAL
**الحالة: غير معتمد — يحتاج نتائج Broker Demo واقعية وتحقق تشغيل يدوي.**
لا تغيّر هذه القائمة صلاحيات التداول برمجياً، ولا تمنح اعتماداً تلقائياً. توقيع المسؤول أو ملف سجلات موثق ضروري قبل فتح صفقة حقيقية. يجب البدء بأصغر أحجام عقود وشروط مخاطرة محددة، وقبول احتمال خسارة كامل رأس المال الصغير، ومراقبة التنفيذ الحي قبل أي توسع.
